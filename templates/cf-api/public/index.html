CF-API

API 中间层服务 — 凭证管理与渠道调度

认证方式

API Key 认证 — 用户端 API 需要在请求头中携带 API Key：
Authorization: Bearer cfapi_xxxxxxxx 或 X-API-Key: cfapi_xxxxxxxx
管理员认证 — 管理端 API 需要 ADMIN_TOKEN：
Authorization: Bearer <admin-token> 或 X-Admin-Token: <admin-token>

健康检查

GET /api/health

服务健康状态，无需认证。返回服务状态和数据库连通性。

凭证管理（需 API Key）

POST /api/tokens/generate

生成新凭证。请求体：

{
  "serviceType": "email_verify",
  "params": { "email": "user@example.com" },
  "idempotencyKey": "optional-key"
}
GET /api/tokens/:id

查询凭证详情（仅限自己的凭证）。

POST /api/tokens/:id/use

使用凭证，提交到渠道处理。

GET /api/tokens/:id/check

查询异步处理结果。

POST /api/tokens/:id/release

释放凭证（终止活跃状态）。

公开用户端

GET /api/user/token/:id

公开查询凭证状态（无敏感数据）。

POST /api/user/token/:id/submit

终端用户提交数据（需 Turnstile 验证）。

Token 状态机

  • unused — 已生成，未使用
  • pending — 已提交渠道，等待结果
  • active — 渠道处理中
  • completed — 成功完成
  • failed — 处理失败
  • expired — 已过期（惰性清理）
  • released — 手动释放

统一响应格式

成功

{ "ok": true, "token": { ... } }

失败

{ "ok": false, "error": "错误描述", "details": { ... } }
