## 修复详情

### 🔴 P0 致命 Bug（功能完全失效）

#### Bug 1: 模式切换工具 radio value 与 JS 逻辑完全不匹配

**影响范围:** `base64-decode`、`url-encode-decode`、`html-escape` — 3 个工具的功能全部反转

**根因:** `tools.njk` 中使用动态模板生成 radio value：
```njk
value="{{ tool.slug.split('-')[0] }}"  →  生成 "base64" / "url" / "html"
```
但 JS 中检查的是固定值：
```js
// base64-decode.js: mode === 'decode'  →  实际收到 'base64'，永远走 else
// url-encode-decode.js: mode === 'encode'  →  实际收到 'url'，永远走 else
// html-escape.js: mode === 'escape'  →  实际收到 'html'，永远走 else
```

**修复:** 每个工具单独硬编码正确的 radio value，与 JS 逻辑严格匹配：
- base64: `value="encode"` / `value="decode"`
- url: `value="encode"` / `value="decode"`
- html: `value="escape"` / `value="unescape"`

**验证:** 渲染后 radio value 与 JS 检查值完全一致 ✅

#### Bug 2: 计算器结果 CSS 类名全部缺失（22个类名）

**影响范围:** `social-insurance-calculator`、`income-tax-calculator` — 两个计算器结果区域完全无样式

**缺失类名:**
- income-tax: `.result-section`, `.result-table`, `.amount`, `.highlight`, `.negative`, `.total`, `.positive`, `.subtitle`, `.recommendation` (9个)
- social-insurance: `.result-section`, `.info-grid`, `.info-item`, `.label`, `.value`, `.small`, `.detail-table`, `.total-row`, `.summary`, `.summary-grid`, `.summary-item`, `.highlight`, `.note` (13个)

**根因:** JS 通过 `innerHTML` 动态生成包含这些 class 的 HTML，但 CSS 文件中从未定义这些样式。

**修复:** 在 `styles.css` 末尾追加完整的计算器结果样式（约 170 行 CSS）。

**验证:** 所有 22 个类名在 CSS 中均有定义 ✅

#### Bug 3: robots.txt 中 sitemap URL 含字面量 `{{ config.url }}`

**影响范围:** SEO — 搜索引擎无法通过 robots.txt 发现 sitemap

**根因:** `addPassthroughCopy` 的 `{ filter: "njk" }` 对纯文本文件不生效，Nunjucks 模板变量不会被解析。

**修复:** robots.txt 使用静态 URL（与 `config.json` 中的 `url` 值同步），恢复为普通 passthrough copy。

**验证:** `_site/robots.txt` 输出正确 URL，无字面量 ✅

---

#### Bug 4: income-tax 除零风险

**影响范围:** `income-tax-calculator` — 月薪为 0 时页面崩溃（显示 `NaN%`）

**根因:**
```js
${((data.annualTax / (data.monthlySalary * 12)) * 100).toFixed(2)}%
```
当 `monthlySalary = 0` 时，`0 / 0 = NaN`。

**修复:** 添加零值保护：
```js
${data.monthlySalary > 0 ? ((data.annualTax / (data.monthlySalary * 12)) * 100).toFixed(2) + '%' : '0.00%'}
```

**验证:** 月薪为 0 时显示 `0.00%` ✅

### 🟡 P1 严重问题（影响生产质量）

#### Issue 5: base64-decode.js 使用已废弃的 escape/unescape API

**影响范围:** `base64-decode` — 部分浏览器可能移除支持

**根因:**
```js
// 废弃 API
result = decodeURIComponent(escape(atob(input)));
result = btoa(unescape(encodeURIComponent(input)));
```

**修复:** 替换为现代 API：
```js
// 解码: 手动构建 %XX 序列
result = decodeURIComponent(atob(input).split('').map(c =>
  '%' + ('00' + c.charCodeAt(0).toString(16)).slice(-2)).join(''));
// 编码: 使用 TextEncoder
result = btoa(String.fromCharCode(...new TextEncoder().encode(input)));
```

**验证:** 中文编解码结果正确 ✅

#### Issue 6: 4 个索引页缺少 canonical URL

**影响范围:** SEO — 首页、工具列表、博客列表、文档列表可能被搜索引擎视为重复内容

**缺失页面:**
- `index.njk` (首页)
- `tools-index.njk`
- `posts-index.njk`
- `docs-index.njk`

**修复:** 在所有 4 个页面的 `eleventyComputed` 中添加 `canonical` 字段。

**验证:** 全部 16 个 HTML 页面均有 canonical URL ✅

#### Issue 7: sitemap.xml 使用硬编码 URL

**影响范围:** 部署到不同域名时 sitemap 指向错误地址

**根因:** sitemap.xml 最初为纯静态文件，URL 写死为 `https://cf-static.pages.dev`。

**修复:** sitemap.xml 使用 Nunjucks 模板语法 `{{ config.url }}`，通过 `{ filter: "njk" }` 在构建时解析。

**验证:** sitemap.xml 正确输出 16 个 URL，无字面量 ✅

---

#### Issue 8: wrangler.toml 使用 npm 而非 pnpm

**影响范围:** 违反项目铁律 3（必须使用 pnpm）

**修复:** `command = "npm run build"` → `command = "pnpm run build"`

---

#### Issue 9: timestamp-converter JS 引用不存在的 DOM 元素

**影响范围:** `timestamp-converter` — JS 尝试获取 `#current-timestamp` 元素但不存在，静默失败

**根因:** `timestamp-converter.js` 第 77-88 行尝试更新 `#current-timestamp` 元素，但模板中未提供该元素。

**影响评估:** 非致命 — JS 有 `if (el)` 保护，不会报错，只是实时时钟功能不生效。

**建议:** 后续可在 timestamp-converter 工具页面添加当前时间戳显示区域。
