## 🔴 严重问题（必须修复）

### 1. `package-lock.json` 存在 — 违反项目铁律 #3

**位置**: 项目根目录

**问题**: `package-lock.json`（108KB）存在于仓库中，说明曾经使用过 `npm install`。项目铁律 #3 明确规定必须使用 `pnpm`。

**此外**: `.gitignore` 中**没有忽略** `package-lock.json`，意味着它可能被提交到 Git 历史中。

**修复**:
```bash
# 删除 npm 产物
rm package-lock.json

# 更新 .gitignore
echo "package-lock.json" >> .gitignore
echo "yarn.lock" >> .gitignore
```

**教训**: 每次创建新项目时，第一时间配置 `.gitignore` 排除非 pnpm 锁文件。

### 2. `og:image` 引用的文件不存在

**位置**: `config.json:12` → `base.njk:22`

**问题**: `config.json` 中定义了 `"ogImage": "/og-image.png"`，但 `_site/og-image.png` 文件不存在。这意味着所有页面的 `og:image` meta 标签指向一个 404 链接。

**影响**: 社交媒体分享时（微信、Twitter、Facebook），卡片不会显示预览图片，严重影响点击率。

**修复方案（二选一）**:
- **方案 A（推荐）**: 创建一张实际的 OG 图片（1200×630px），放入 `assets/` 目录
- **方案 B（临时）**: 从 `config.json` 中移除 `ogImage` 字段，避免输出无效 meta 标签

---

### 3. `BreadcrumbList` Schema 在索引页错误输出

**位置**: `base.njk:113-166`

**问题**: BreadcrumbList JSON-LD 的条件是 `{% if page.url and page.url != '/' %}`，这意味着 `/tools-index/`、`/posts/`、`/docs/` 这些索引页也会输出 BreadcrumbList。但条件内部的 `'/tools/' in page.url` 等检查不会匹配这些页面，导致输出一个**只有首页一项的 BreadcrumbList**：

```json
{
  "@type": "BreadcrumbList",
  "itemListElement": [
    {
      "@type": "ListItem",
      "position": 1,
      "name": "首页",
      "item": "https://cf-static.pages.dev/"
    }
  ]
}
```

**影响**: Google 可能将此视为低质量结构化数据标记。

**修复**: 条件应与面包屑导航保持一致：
```njk
{% if page.url and page.url != '/' and page.url != '/tools-index/' and page.url != '/posts/' and page.url != '/docs/' %}
```

### 4. 缺少 CSP（内容安全策略）Header

**位置**: `_headers`

**问题**: 当前安全头缺少 `Content-Security-Policy`。虽然站点是纯静态的，但工具页面包含内联 `<script>`（JSON-LD）和内联 `onclick` 处理器，需要正确配置 CSP。

**影响**: 没有 CSP 保护，如果站点被中间人攻击注入恶意脚本，没有额外防护层。

**修复方案**:
```
# _headers 添加
/*
  Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
```

**注意**: 由于 JSON-LD 使用内联 `<script type="application/ld+json">`，需要 `'unsafe-inline'`。这是可接受的，因为 JSON-LD 脚本不会被执行。

### 5. 工具页面缺少 `<form>` 标签 — 可访问性问题

**位置**: `tools.njk:27-75`

**问题**: 所有工具输入区域使用裸 `<textarea>`、`<input>`、`<button>` 元素，没有包裹在 `<form>` 标签中。这意味着：
- 用户按 Enter 键不会触发表单提交
- 屏幕阅读器无法正确识别表单区域
- 浏览器自动填充功能无法工作

**修复**: 将工具输入区域包裹在 `<form>` 标签中：
```njk
<form class="tool-form" onsubmit="processTool(); return false;">
  <!-- 现有输入元素 -->
  <div class="tool-actions">
    <button type="submit" class="btn-primary">处理</button>
    <!-- ... -->
  </div>
</form>
```

## 🟡 重要问题（应该修复）

### 6. 缺少 `<meta hreflang>` 标签

**位置**: `base.njk` `<head>`

**问题**: 纯中文站缺少 `hreflang` 声明。Google 需要此标签来正确识别页面语言。

**修复**:
```njk
<meta http-equiv="content-language" content="zh-CN">
<link rel="alternate" hreflang="zh-CN" href="{{ canonical | default(config.url ~ page.url) }}">
```

---

### 7. `tools-index` 页面缺少 JSON-LD Schema

**位置**: `tools-index.njk`

**问题**: 工具列表页没有 `CollectionPage` 或 `ItemList` Schema，搜索引擎无法理解这是一个工具集合页面。

**修复**: 在 `tools-index.njk` 底部添加：
```njk
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "CollectionPage",
  "name": "所有工具",
  "description": "免费在线开发工具集合",
  "url": "{{ config.url }}/tools-index/",
  "hasPart": [
    {% for tool in tools %}
    {
      "@type": "SoftwareApplication",
      "name": "{{ tool.title }}",
      "url": "{{ config.url }}/tools/{{ tool.slug }}/",
      "description": "{{ tool.description }}"
    }{% if not loop.last %},{% endif %}
    {% endfor %}
  ]
}
</script>
```

### 8. Sitemap 格式不干净 + changefreq 偏激进

**位置**: `sitemap.njk`

**问题**:
1. 每个 `<url>` 条目之间有空白行（XML 格式不整洁）
2. 工具页 `changefreq` 为 `monthly`，但工具页面内容几乎不变，应为 `yearly`
3. 缺少 `<lastmod>` 字段（除了 posts）

**修复**:
- 清理 sitemap.njk 模板中的空白行
- 工具页 `changefreq` 改为 `yearly`
- 为所有条目添加 `<lastmod>`（使用 `{% if tool.date %}` 或构建时间）

---

### 9. Footer 年份硬编码

**位置**: `base.njk:69`

**问题**: `&copy; 2026` 硬编码，明年需要手动更新。

**修复**: 在 `.eleventy.js` 中添加全局数据：
```js
eleventyConfig.addGlobalData("currentYear", () => new Date().getFullYear());
```
模板中改为：
```njk
&copy; {{ currentYear }} {{ config.siteName }}. 保留所有权利。
```

### 10. 内联 `onclick` 处理器

**位置**: `tools.njk:62-64`

**问题**: 8 个工具页面使用内联 `onclick="processTool()"` 等处理器。虽然不是致命问题，但不符合现代前端最佳实践（关注点分离）。

**影响**: 如果未来添加 CSP `script-src 'self'`（不含 `'unsafe-inline'`），这些按钮将失效。

**建议**: 在 JS 文件中通过 `addEventListener` 绑定事件。但这需要较大重构，优先级可放低。

---

### 11. `tools-index`、`posts-index`、`docs-index` 缺少 SEO 内容区块

**位置**: 各 index 页面

**问题**: 这些索引页只有 h1 + 一句话描述 + 卡片列表，对搜索引擎来说内容太薄。

**建议**: 在每个索引页底部添加 SEO 内容区块（类似首页的"为什么选择在线开发工具？"），用 200-300 字描述该类别的价值。

## 🟢 改进建议（可以优化）

### 12. 缺少 `llms.txt`

**位置**: 项目根目录

**问题**: AI 爬虫（如 ChatGPT、Perplexity）会查找 `llms.txt` 来了解站点结构和内容。缺少此文件意味着 AI 产品无法准确引用你的站点。

**建议**: 创建 `src/llms.txt`：
```
# 在线开发工具
# https://cf-static.pages.dev

## 简介
免费在线开发工具集合，所有操作在浏览器中完成，数据不上传服务器。

## 工具列表
- JSON 格式化: /tools/json-formatter/
- Base64 编解码: /tools/base64-decode/
- ...

## 博客
- /posts/

## 文档
- /docs/
```

---

### 13. 缺少 Web App Manifest

**位置**: 项目根目录

**问题**: 没有 `manifest.json`，用户无法将站点"添加到主屏幕"（PWA 体验）。

**建议**: 创建基础 manifest：
```json
{
  "name": "在线开发工具",
  "short_name": "开发工具",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#0f1117",
  "theme_color": "#6366f1",
  "icons": [
    {
      "src": "/favicon.svg",
      "sizes": "any",
      "type": "image/svg+xml"
    }
  ]
}
```

### 14. 缺少 preconnect / DNS-prefetch

**位置**: `base.njk` `<head>`

**问题**: 虽然站点没有外部资源依赖，但如果未来添加分析脚本（如 Google Analytics），预连接能提升性能。

**当前评估**: 暂无外部资源，此项优先级低。

---

### 15. CSS 体积可优化

**位置**: `assets/styles.css`

**问题**: CSS 文件 18.5KB（未压缩）。虽然不算大，但有死代码：
- `.navbar`、`.logo`、`.nav-links` 等多处选择器定义了但对应 HTML 结构可能不匹配
- `.article-container`、`.article-header` 等博客文章样式在当前内容中可能未使用

**建议**: 使用 `purgecss` 或 `cssnano` 在构建时移除未使用的 CSS。

---

### 16. JS 文件未压缩

**位置**: `assets/js/`

**问题**: JS 文件总计 44KB（未压缩），直接透传到输出目录，没有经过 minify。

**建议**: 添加构建时压缩步骤：
```json
// package.json
"build": "eleventy && npx terser assets/js/*.js -o _site/assets/js/min.js"
```
或使用 11ty 插件 `@11ty/eleventy-plugin-minify`。
