# 026 社交登录 Admin 运营开关（Phase A）

> 日期：2026-08-04  
> 范围：**运维开关版** — 后台可启用/禁用、排序、改展示名；**密钥仍在 env / Cloudflare secrets**  
> 状态：已实施

## 1. 问题

此前上游社交 IdP 仅由代码注册表 + 环境变量决定：

- `SOCIAL_PROVIDER_REGISTRY`（支持哪些源）
- `*_CLIENT_ID` / `*_CLIENT_SECRET`（是否成对配置）
- `ENABLED_SOCIAL_PROVIDERS`（可选 allowlist）

要临时下线某个登录按钮，必须改 secret / wrangler / 重启，不够灵活。

## 2. 行业实践分层（本阶段采用）

| 层 | 内容 | 变更成本 |
|----|------|----------|
| **代码注册表** | 支持的 provider 集合与默认文案 | 发版 |
| **密钥 / 能力** | Client ID/Secret、env allowlist | 运维 secrets |
| **运营策略** | 启用、排序、展示名 | **Admin 即时** |

这与 Auth0 / Cognito / Keycloak 常见拆分一致：**连接能力**与**产品开关**分离。  
**Phase A 明确不做**：把 Client Secret 写入 DB 或经 Admin API 录入（属 Phase B，需加密与审计强化）。

## 3. 有效集合公式

```
effective =
  在 SOCIAL_PROVIDER_REGISTRY
  ∩ env 密钥成对齐全
  ∩ ENABLED_SOCIAL_PROVIDERS 放行（空 = 不限制）
  ∩ social_provider_config.enabled（无行时默认 true）
```

- 登录页、`GET /api/auth-meta/social`、以及 `GET /api/health` 的 `socialProviders` 只反映 **effective** 项（含 Admin 覆盖的 `label`）。
- `createAuth` 仍注入「密钥齐全」的全部 provider（避免 Worker 长生命周期缓存与 DB 开关脱节）。
- 运行时门禁（非 effective → **403** `social_provider_disabled`）：
  - `POST /api/auth/sign-in/social`
  - `POST /api/auth/link-social`（已登录绑源；与 sign-in 同等运营策略）
  - `/api/auth/callback/{id}`

## 4. 数据模型

表 `social_provider_config`（**无 secret 列**）：

| 列 | 说明 |
|----|------|
| `provider_id` | PK，须为注册表 id |
| `enabled` | 运营开关 |
| `sort_order` | 登录页顺序 |
| `display_label` | 可空；空则用注册表默认 |
| `updated_at` / `updated_by_email` | 审计辅助 |

迁移：`src/db/migrate.ts` 幂等 `CREATE TABLE IF NOT EXISTS`。

## 5. Admin API

均需平台管理员（session 或 `X-Admin-Api-Key`）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/social-providers` | 全量状态：enabled / credentialsConfigured / inEnvAllowlist / effective 等；**无 secret** |
| PATCH | `/api/admin/social-providers/:id` | `enabled` / `displayLabel` / `sortOrder`；启用时校验密钥与 allowlist |
| PUT | `/api/admin/social-providers/order` | body `{ orderedIds: string[] }` 须覆盖注册表全部 id |

审计：`social_provider.update`、`social_provider.reorder`。

## 6. Admin UI

- 路由：`/admin/social`
- 菜单：**社交登录**
- 能力：开关、上移/下移排序、编辑展示名；无密钥时不可打开启用开关

## 7. 运维说明

1. **首次上线**：无 DB 行时行为与 Phase A 前一致（密钥 + allowlist 即开）。
2. **临时关 Google**：Admin 关掉 Google → 无需改 secrets。
3. **彻底下线**：Admin 禁用 + 从 `ENABLED_SOCIAL_PROVIDERS` 移除或撤 secret（双保险）。
4. **新 IdP**：仍须代码注册表 + secrets；Admin 不能凭空「创建」未注册源。

## 9. 与多 RP 的关系

社交运营开关是 **平台级**（登录页 / meta / sign-in·link·callback 门禁），**不是**按 OAuth client 裁剪。  
多项目同一用户的 client 隔离见 docs/014「多项目同一用户」；本 Phase 不改变 code/token 的 client 绑定。
