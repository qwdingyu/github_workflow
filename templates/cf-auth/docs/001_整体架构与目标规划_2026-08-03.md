> 日期：2026-08-03

## 一、为什么要独立 cf-auth

### 1.1 业务动机

你有多个项目（抽奖、商城、表单等）需要复用登录能力。若让各业务直接共享 Better Auth 的 session cookie，会快速踩到：

- 浏览器 SameSite / 第三方 Cookie 限制  
- 跨域 CSRF  
- 登出同步困难  
- 认证服务无法独立升级  

**正确边界是标准 OAuth/OIDC：**

```text
auth.eforge.xyz  (Identity Provider / 身份服务)
        |
        |  Authorization Code + PKCE
        v
各业务项目 (Relying Party)
  - 自己的登录态 / 业务 JWT
  - 自己的用户映射表
  - 不直连 auth 数据库
```

### 1.2 与 cf-lottery 的关系

| 项目 | 职责 |
|------|------|
| **cf-auth** | 身份：注册/登录、Google、session、OAuth 发码、token、JWKS、consent |
| **cf-lottery** | 业务：活动参与、限流、Turnstile、开奖、领奖、租户 RBAC |

cf-lottery 已在根项目完成 Better Auth **最小技术验证**（见 docs/056）：

- `better-auth@1.6.25`  
- Hono `auth.handler(c.req.raw)`  
- libSQL 临时 SQLite + Drizzle adapter  
- 邮箱注册/登录/session 查询通过  
- Google provider **仅**验证到授权 URL 生成，**未**验证真实 Google 回调  

结论沿用 056/055b：

- **可以**启动独立 cf-auth  
- **现在不能**删除 Logto  
- **现在不能**让业务项目读 auth 库

## 二、产品目标

### 2.1 一句话

把 Better Auth 做成 **轻量统一认证微服务**，以 **OAuth 2.1 / OIDC 兼容 Provider** 对外，部署在 `auth.eforge.xyz`，同时兼容：

1. **Cloudflare Workers**（优先生产形态）  
2. **云服务器 / 本地 Node**（调试与兜底）

### 2.2 阶段目标（本期规划范围）

| 阶段 | 目标 | 不在本期 |
|------|------|----------|
| P0 | 仓库脚手架 + 本地 Node + file SQLite 跑通 health / Better Auth handler | 真实 Google 回调 |
| P1 | OAuth Provider 插件 + 最小 consent/login 页 + 本地 client 授权码闭环 | 动态 client 注册对公网开放 |
| P2 | Cloudflare 部署到 `auth.eforge.xyz` + secrets + 自定义域名 | 全量替换 Logto |
| P3 | cf-lottery 作为第一个 OAuth client 接入（参与端） | 管理端全面迁出 Logto |
| P4 | 第二业务项目接入后评估删 Logto | Keycloak / authentik |

### 2.3 非目标（明确不做）

- 不做跨域共享 Better Auth cookie 作为多项目主方案  
- 不做企业级 IAM（Keycloak/authentik）  
- 不让业务项目直连 D1/Turso auth 库  
- 第一阶段不追求全局单点登出（SLO）完美同步  
- 第一阶段不开放未认证的 Dynamic Client Registration

## 三、目标架构

```text
                         ┌─────────────────────────────────────┐
                         │         auth.eforge.xyz             │
                         │         (cf-auth Worker/Node)       │
                         │                                     │
                         │  Better Auth core                   │
                         │   - user / session / account        │
                         │   - 多社交 socialProviders          │
                         │     (Google/GitHub/… 注册表按 env)  │
                         │   - Turnstile（后续）               │
                         │                                     │
                         │  Plugins                            │
                         │   - @better-auth/oauth-provider     │
                         │   - jwt（OAuth Provider 依赖）      │
                         │                                     │
                         │  Storage                            │
                         │   - 主库：D1 或 libSQL/SQLite       │
                         │   - 辅存：KV（session/cache/限流）  │
                         └──────────────────┬──────────────────┘
                                            │
                     Authorization Code + PKCE + openid profile email
                                            │
              ┌─────────────────────────────┼─────────────────────────────┐
              v                             v                             v
     lucky.eforge.xyz              project-b.example              shop.example
     (cf-lottery RP)               (未来 RP)                      (未来 RP)
     本地业务 JWT/session          本地业务态                     本地业务态
     identity_type=auth_user
     identity_value=issuer:sub
```

### 3.1 身份模型（给业务项目）

业务项目 **只**信任：

| 字段 | 含义 |
|------|------|
| `iss` | `https://auth.eforge.xyz`（或配置的 issuer） |
| `sub` | Better Auth 用户稳定 ID |
| `email` / `email_verified` / `name` / `picture` | 标准 OIDC claims（按 scope） |

cf-lottery 参与端建议映射（规划，待 P3 实施）：

```text
identity_type  = "auth_user"
identity_value = "https://auth.eforge.xyz" + ":" + sub
```

同活动同身份唯一参与；Turnstile + DB 限流仍在 lottery 侧；高价值领奖再二次校验。

### 3.2 Session 边界（必须分清）

| 会话 | 存放位置 | 用途 |
|------|----------|------|
| **Auth session** | 仅 `auth.eforge.xyz` 的 Cookie（Better Auth） | 用户在 IdP 上是否已登录、consent |
| **业务 session / JWT** | 各 RP 自己域 | 业务授权、租户、角色 |

**禁止**：业务前端直接依赖 `better-auth.session_token` 跨域读取。

## 四、技术选型（规划冻结）

### 4.1 已由 cf-lottery 验证的栈

| 组件 | 版本/事实 | 来源 |
|------|-----------|------|
| better-auth | `1.6.25` | package.json + smoke 通过 |
| Hono | `^4.12.22` | cf-lottery |
| drizzle-orm | `0.45.2` | 与 drizzle-adapter peer 对齐 |
| @libsql/client | `^0.14.0` | 本地 file + 远程 Turso |
| @hono/node-server | 已用 | `src/server.ts` 双平台 |
| wrangler | `4.114.0`（本地 CLI 已登录） | whoami 成功 |

### 4.2 本项目新增（npm 已核实存在）

| 包 | 版本 | 用途 |
|----|------|------|
| `@better-auth/oauth-provider` | `1.6.25` | OAuth 2.1 Provider（官方推荐，替代旧 oidc-provider） |
| `better-auth` 内 `jwt` plugin | 随 better-auth | OAuth Provider 文档示例要求配合 `jwt()` |
| `@better-auth/drizzle-adapter` | 传递依赖 / 可显式装 `1.6.25` | Drizzle 适配 |

> 安装注意（056 实踩）：`npm install better-auth@1.6.25` 可能需 `--legacy-peer-deps`；lockfile 固定后 CI 用 `npm ci`。

### 4.3 部署形态优先级

| 优先级 | 形态 | 适用 |
|--------|------|------|
| 1 | Cloudflare Workers +（D1 或 libSQL）+ KV | 生产首选，贴合 eforge 技术栈 |
| 2 | Node + file SQLite / 远程 libSQL | 本地开发、云服务器兜底 |
| 3 | Keycloak 等 | **不做** |

**双平台兼容策略（借鉴 048，不照搬业务）：**

```text
src/
  index.ts          # Workers 入口 export default { fetch }
  server.ts         # Node 入口 @hono/node-server
  app.ts            # 共享 Hono app（业务/认证路由）
  lib/platform.ts   # getEnv / getClientIp / waitUntil
  lib/auth.ts       # betterAuth 工厂（按 runtime 注入 database）
  lib/db.ts         # 数据库工厂（D1 | libSQL file | libSQL remote）
```

同一套 `app.fetch`，差异收敛到入口与 `lib/*`。

## 五、数据归属

### 5.1 Auth 库内（仅 cf-auth）

Better Auth 核心表（056 已用）：

- `user`  
- `session`  
- `account`  
- `verification`  

OAuth Provider 插件 schema（从 `@better-auth/oauth-provider@1.6.25` 类型定义核实）：

- `oauthClient`  
- `oauthRefreshToken`  
- `oauthAccessToken`  
- `oauthConsent`  

另有 JWT 插件可能需要 jwks/密钥相关表或配置——**实施时用官方 `npx auth generate` / migrate 生成，不手写猜字段**。

### 5.2 不进 Auth 库

- lottery 活动、参与记录、租户、RBAC  
- 业务侧用户映射表（可存 `issuer + sub`）

## 六、安全基线（规划）

1. **HTTPS only** 生产；`baseURL` 固定为 `https://auth.eforge.xyz`（或动态 baseURL 的 allowedHosts 白名单）。  
2. **trustedOrigins** 显式列出 RP 与自身 origin。  
3. OAuth client **redirect_uri 白名单**；生产禁止随意 `http://`（localhost 调试除外，插件类型注释写明 HTTPS 强制、localhost 例外）。  
4. 首批 client **手工注册**；`allowDynamicClientRegistration` / `allowUnauthenticatedClientRegistration` 默认 **false**（包默认值亦为 false）。  
5. 业务 RP 使用 **Authorization Code + PKCE**；SPA 用 public client + PKCE。  
6. Secrets 只走 `wrangler secret` / `.env`（不进 git）。  
7. Workers Free：避免登录路径高 CPU KDF（参见 023）；优先 Google 登录，邮箱密码若开则评估 CPU。  
8. Rate limit：Better Auth 内置 + 可选 KV 辅存。

## 七、对 cf-lottery 的远期接入（仅规划）

```text
1. 用户点击参与
2. 跳转 auth.eforge.xyz（OAuth authorize）
3. Google / 已有 session 登录
4. consent（若需要）
5. redirect 回 lottery callback
6. lottery 换 token，取 sub
7. 写 identity_type/value
8. 本域发业务 cookie/JWT
9. Turnstile + 限流继续
```

**P3 前不动 lottery 生产认证主路径；Logto 保留回退。**

## 九、决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 多项目复用边界 | OAuth/OIDC，非共享 Cookie | 浏览器与 CSRF 现实 |
| Provider 插件 | `@better-auth/oauth-provider` | 官方 1.5+ 方向；旧 oidc-provider 将弃用 |
| 运行时 | Hono multi-runtime | 与 lottery 一致，双平台成本低 |
| 本地库 | file SQLite via libSQL | 050 已验证模式 |
| 生产库 | **优先验证** D1；**兜底** 远程 libSQL/Turso | 见 005：1.6.25 包内未直接检出 D1Database 符号，实施时必须实测 |
| 域名 | auth.eforge.xyz | 用户指定；DNS 已解析到 Cloudflare 任播地址 |
