# 024 Admin 硬删除：测试垃圾清理与防灾难

> 日期：2026-08-04  
> 背景：生产/联调产生测试 client、用户垃圾数据；运营需要受控删除。  
> 前置：docs/020 曾**禁止**批量删 client/user——本轮在**严格护栏**下有条件开放，**不**开放审计删除。

## 1. 设计原则（防灾难）

| 规则 | 实现 |
|------|------|
| 显式 id 列表 | 禁止无 where 整表删 |
| 硬删除上限 **10** | 严于启停/封禁 20（`HARD_DELETE_BATCH_MAX`） |
| 二次确认 | body 必须 `confirm: "DELETE"`（字面量） |
| 前端确认框 | 文案标明不可逆 + 影响面 |
| 串行 + 逐条 audit | `client.delete` / `user.delete` |
| 禁删管理员 | `ADMIN_EMAILS` / `ADMIN_USER_IDS` 命中 → 403 |
| 禁删本人 | session 管理员 `actorUserId === target` → 403 |
| 审计不可删 | 仍无 `DELETE /audit` |
| Blocklist | 已有 remove / batch-remove（删条目，非用户） |

## 2. API

| 方法 | 路径 | Body |
|------|------|------|
| POST | `/api/admin/clients/:clientId/delete` | `{ "confirm": "DELETE" }` |
| POST | `/api/admin/clients/batch-delete` | `{ "confirm": "DELETE", "clientIds": [...] }` 1–10 |
| POST | `/api/admin/users/:userId/delete` | `{ "confirm": "DELETE" }` |
| POST | `/api/admin/users/batch-delete` | `{ "confirm": "DELETE", "userIds": [...] }` 1–10 |

## 3. 删除语义

### Client
1. 按 `clientId` 删除 `oauthRefreshToken` / `oauthAccessToken` / `oauthConsent`  
2. 删除 `oauthClient` 行  
3. **不**删用户；**不**动 audit

### User
1. `revokeAllAccessForUser`  
2. 显式删除 refresh/access/consent/session/account（不依赖 SQLite FK 是否开启）  
3. `oauthClient.userId` 置 null  
4. 移除 `auth_blocklist` 中该 `user_id` 与精确 `email`（**不**删 `email_domain`）  
5. 删除 `user` 行  
6. 白名单管理员 / 本人 → 拒绝

## 4. 前端

- **Clients**：行「硬删除」+ 批量「硬删除」  
- **Users**：行「硬删除」+ 批量「硬删除」  
- **确认框**：须键入字面量 `DELETE` 后按钮才可点（与服务端 `confirm` 对齐，防误点）  
- **Blocklist**：沿用「批量移除」（删除黑名单行）  
- **Audit**：仍仅导出，无删除按钮  

## 5. 运营建议

- 生产 RP client：优先 **禁用**，确认无流量后再硬删  
- 正式用户：优先 **封禁**；硬删会破坏 RP 侧 `sub` 映射  
- 仅清理确认的测试垃圾时使用硬删除  

## 6. 验证

npm run verify
# 含：无 confirm → 400；白名单用户 → 403；普通用户/client 可删；batch 上限 11 → 400
