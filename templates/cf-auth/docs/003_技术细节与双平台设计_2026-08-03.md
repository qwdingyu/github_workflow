## 一、运行时与入口

### 1.1 双入口（对齐 cf-lottery 048）

| 入口 | 命令 | 场景 |
|------|------|------|
| `src/server.ts` | `npm run dev:local` → `tsx src/server.ts` | 本地 / 云服务器 |
| `src/index.ts` | `wrangler dev` / `wrangler deploy` | Cloudflare Workers |

共享：

```text
createApp(env) → Hono app
app.fetch(request, env, ctx)
```

Node 侧：

- 用中间件把 `process.env` 注入 `c.env`  
- `@hono/node-server` 的 `serve({ fetch: app.fetch })`  
- 静态：login/consent 简单页面可用 `serveStatic` 或内联 HTML  

Workers 侧：

```ts
export default {
  fetch(request, env, ctx) {
    return app.fetch(request, env, ctx);
  },
};
```

### 1.2 端口规划

| 服务 | 端口 | 原因 |
|------|------|------|
| cf-lottery 本地 | 8787 | 已占用 |
| cf-auth 本地 | **8788** | 避免冲突 |
| wrangler dev auth | 8788 或 8790 | 写入 package scripts 固定 |

### 1.3 Better Auth 与 Hono

**已验证（056）：**

```ts
app.on(["GET", "POST"], "/api/auth/**", (c) => auth.handler(c.req.raw));
```

**Node 官方另有：** `better-auth/node` → `toNodeHandler` / `fromNodeHeaders`（包内 `integrations/node.d.mts` 存在）。  
本项目优先 **统一走 Hono + `auth.handler(Request)`**，减少双实现。

**注意：** 官方 Hono 文档页在自动抓取时正文不完整；以 056 实测 + handler 标准 Request/Response 为准。

## 二、环境变量设计

### 2.1 公共

| 变量 | 必填 | 说明 |
|------|------|------|
| `BETTER_AUTH_SECRET` | 是 | ≥32 字符；可用官方 secrets 轮换格式（1.5 起支持多版本） |
| `BETTER_AUTH_URL` / `BASE_URL` | 是 | 生产 `https://auth.eforge.xyz`；本地 `http://localhost:8788` |
| `TRUSTED_ORIGINS` | 是 | 逗号分隔；含自身与 RP |
| `GOOGLE_CLIENT_ID` | M5 | Google OAuth |
| `GOOGLE_CLIENT_SECRET` | M5 | secret |
| `TURNSTILE_SECRET_KEY` | 后期 | 服务端校验 |
| `TURNSTILE_SITE_KEY` | 后期 | 前端 |
| `TRUST_PROXY_HEADERS` | Node 反代 | 仅可信反代时 `true`（同 lottery platform） |

### 2.2 数据库（二选一或按 runtime）

**路径 A — libSQL（本地 file / 远程 Turso，050 模式）：**

| 变量 | 说明 |
|------|------|
| `DATABASE_URL` 或 `TURSO_URL` | `file:./data/local.db` 或 `libsql://...` |
| `TURSO_TOKEN` | 远程需要；file 可空 |

**路径 B — D1（Workers binding）：**

| Binding | 说明 |
|---------|------|
| `DB` | D1Database，库名建议 `cf-auth`（已存在空库） |

**实现约束：** `lib/db.ts` / `lib/auth.ts` 按 runtime 分支创建 adapter，**业务路由不感知**。

### 2.3 KV（可选 secondary storage）

| Binding | 建议用途 |
|---------|----------|
| `AUTH_KV` 或复用经确认的 KV | rate limit、verification 短期、client 缓存 |

## 三、Auth 工厂设计

```ts
// 伪代码规格 — 实施时按官方 API 落盘
function createAuth(options: {
  baseURL: string;
  secret: string;
  db: DrizzleDB | D1Database; // 具体类型以实测为准
  trustedOrigins: string[];
  google?: { clientId: string; clientSecret: string };
}) {
  return betterAuth({
    baseURL: options.baseURL,
    secret: options.secret,
    trustedOrigins: options.trustedOrigins,
    database: /* drizzleAdapter 或 D1 直绑 */,
    emailAndPassword: { enabled: true }, // 本地调试；生产可关或限流
    socialProviders: options.google
      ? { google: options.google }
      : undefined,
    plugins: [
      jwt(), // OAuth Provider 官方示例依赖
      oauthProvider({
        loginPage: "/sign-in",
        consentPage: "/consent",
        // scopes 默认含 openid profile email offline_access
        allowDynamicClientRegistration: false,
        allowUnauthenticatedClientRegistration: false,
        // codeExpiresIn / accessTokenExpiresIn 可用默认
      }),
    ],
  });
}
```

### 3.1 OAuth Provider 必填项（包类型核实）

从 `@better-auth/oauth-provider@1.6.25` 的 `OAuthOptions`：

- **`loginPage: string`** — 必填  
- **`consentPage: string`** — 必填  

重要可选项与默认（类型注释）：

| 选项 | 默认/说明 |
|------|-----------|
| `scopes` | `openid profile email offline_access` |
| `accessTokenExpiresIn` | 3600 |
| `idTokenExpiresIn` | 36000 |
| `refreshTokenExpiresIn` | 2592000 |
| `codeExpiresIn` | 600 |
| `grantTypes` | authorization_code, client_credentials, refresh_token |
| `allowDynamicClientRegistration` | false |
| `allowUnauthenticatedClientRegistration` | false（且注释称未来可能弃用该支持） |

### 3.2 端点（插件声明，路径相对 Better Auth basePath）

类型中可见：

- `GET /.well-known/oauth-authorization-server`（server-only helper；若 basePath 非根，文档提示可手动导出 metadata handler）  
- `GET /.well-known/openid-configuration`  
- `GET /oauth2/authorize`  
- `POST /oauth2/consent`  
- 以及 token / client CRUD 等（实施时对照 OpenAPI 与 smoke）  

**导出包还提供：**

- `oauthProviderAuthServerMetadata(auth)`  
- `oauthProviderOpenIdConfigMetadata(auth)`  

当 Better Auth `basePath` 为 `/api/auth` 时，well-known 可能不在域名根——**M3/M4 必须实测路径**，必要时在 Hono 根路由手动挂 metadata。

### 3.3 basePath 建议

```text
Better Auth basePath: /api/auth
完整例：https://auth.eforge.xyz/api/auth/...
OAuth authorize 可能为：https://auth.eforge.xyz/api/auth/oauth2/authorize
```

以插件实际挂载为准；文档与 RP 配置必须用实测 URL。

## 四、数据库 Schema 策略

### 4.1 生成方式（最佳实践）

1. 写好 `auth` 配置后执行官方：

```bash
npx auth generate
# 或项目内 drizzle-kit generate
```

2. **禁止**长期手写与官方不一致的猜字段。  
3. 056 smoke 的表结构可作 **参考**，正式以 generate 输出 + migrate 为准。  

### 4.2 OAuth 额外表（类型 schema 核实的字段摘要）

**oauthClient（关键字段）：**

- `clientId` unique  
- `clientSecret` optional（public client 可空）  
- `redirectUris` string[] **required**  
- `postLogoutRedirectUris` optional  
- `name`, `uri`, `icon`, `disabled`, `skipConsent`  
- `public`, `requirePKCE`  
- `grantTypes`, `responseTypes`, `scopes`  
- `tokenEndpointAuthMethod`  
- `userId` / `referenceId` 归属  

**oauthRefreshToken / oauthAccessToken / oauthConsent：**  
与 clientId、userId、sessionId、scopes、expiresAt 关联；access token 注释强调与 session 绑定、introspection 时校验 session。

### 4.3 迁移

| 环境 | 方式 |
|------|------|
| 本地 file SQLite | `scripts/migrate.mjs` + drizzle 或 SQL |
| Turso | 同 lottery `migrate.mjs` 模式 |
| D1 | `wrangler d1 migrations apply cf-auth` |

## 七、RP 接入规格（给 cf-lottery）

### 7.1 Client 配置示例

```text
client_id:       cf-lottery-web
client_type:     public（SPA）或 confidential（BFF）
redirect_uris:   https://lucky.eforge.xyz/auth/callback
                 http://localhost:8787/auth/callback
require_pkce:    true
scopes:          openid profile email
```

### 7.2 推荐流

1. lottery 前端生成 `state` + PKCE `code_verifier`  
2. 浏览器跳转 auth authorize  
3. 回调 lottery，BFF 或前端换 token（SPA 更推荐 BFF 持有 secret；纯 SPA 用 public+PKCE）  
4. 校验 `id_token`（iss、aud、nonce、签名 via JWKS）  
5. 建立 lottery 自己的 session  
6. 持久化 `identity_value = iss + ":" + sub`  

### 7.3 禁止

- 前端长期存 auth refresh token 无保护  
- 直连 auth 数据库查 user  
- 把 Better Auth cookie 域设成 `.eforge.xyz` 当 SSO 捷径（反模式）

## 八、Cloudflare Workers 注意点

1. **CPU 10ms（Free）**：Google OAuth 主路径以网络 I/O 为主；避免重哈希。  
2. **兼容性日期**：与 lottery 可对齐 `2026-05-24` 或更新官方推荐。  
3. **自定义域名**：`wrangler.jsonc` routes `custom_domain: true`（lottery 对 `lucky.eforge.xyz` 已用此模式）。  
4. **secrets**：永不进 `vars`。  
5. **D1 限制**：官方 1.5 博文写明 D1 **无 interactive transactions**，Better Auth 用 `batch()`；实施时回归写密集路径。  
6. **创建 auth 实例**：Workers 上注意是否每请求 `betterAuth()`；若有性能问题再缓存到模块作用域（小心 env 不同）。
