# 014 RP 接入手册（第二、第三个业务项目）

> 日期：2026-08-03  
> 项目：cf-auth  
> 权威实现样本：cf-lottery（`cf-auth-oauth.ts` / `idp-user-provision` / `useCfAuthLogin`）

---

## 一、原则（不要违反）

1. **每个业务项目一个 OAuth Client**（独立 `client_id` / secret / redirect_uris）。  
2. **协议**：Authorization Code + **PKCE**；业务自签本地 JWT/session，**不**共享 cf-auth Cookie。  
3. **身份主键**：业务侧绑定 `(provider=cf-auth, sub)`；`sub` = cf-auth `user.id`。  
4. **第一方** 才可 `skip_consent=true`；**默认保持** `require_pkce=true`（Authorization Code + PKCE）。字段语义、第一方白名单、排障见 **docs/027**。  
5. **禁止**业务直连 Turso auth 库；**禁止**公网 Dynamic Client Registration。

### 多项目同一用户（共享 vs 隔离）

| 维度 | 行为 | 说明 |
|------|------|------|
| auth 域 session | **共享** | 用户在 `auth.eforge.xyz` 登录一次后，可向多个已注册 RP 授权（SSO） |
| `sub` / `user.id` | **共享**（默认 public subject） | 同一自然人在各 RP 看到同一 `sub`，便于跨项目识别；**不是**账号串号 |
| client / secret / redirect | **隔离** | 每项目独立；错误 `redirect_uri` 不能出码 |
| authorization code | **隔离 + 单次** | code 绑定 `client_id`；跨 client 换码失败；错误尝试会消耗 code |
| access / refresh / id_token | **隔离** | 行内 `clientId`；`id_token.aud`（及 azp）绑定本 client |
| consent | **按 client** | `oauthConsent` 含 `clientId` + `userId` |
| 上游社交开关 | **平台级** | Admin 社交启用/禁用对所有 RP 的登录页生效（非 per-client） |

**RP 必须做**：校验 `id_token` 的 `iss` / `aud`（= 本 client_id）/ 签名；用**本 client** 换到的 token 建业务 session。  
**不得做**：把 A 项目的 access_token 当 B 项目的登录凭证；共享 cf-auth Cookie 到业务域。

## 二、标准步骤

```text
① 在 cf-auth 注册 OAuth client
   - 浏览器：https://auth.eforge.xyz/admin/clients（平台管理员）
   - 或 API：POST /api/admin/clients（X-Admin-Api-Key 或管理员 session）
   - 或脚本：`ADMIN_API_KEY=... node scripts/register-oauth-client.mjs`（优先 Admin API；BA create-client 已收口）
② 保存一次明文 client_secret（之后无法再看）
③ 业务 env：
   CF_AUTH_ISSUER=https://auth.eforge.xyz
   CF_AUTH_CLIENT_ID=...
   CF_AUTH_CLIENT_SECRET=...
   CF_AUTH_REDIRECT_URI=https://your.app/auth/callback
   CF_AUTH_ENABLED=true
④ 前端：authorize + PKCE + state（抄 lottery useCfAuthLogin）
⑤ 后端：code → token → userinfo → 本地 provision → 发业务 JWT
⑥ cf-auth TRUSTED_ORIGINS 增加业务 origin，redeploy
⑦ smoke：authorize → callback → 业务 session
```

### Admin 创建 client 示例

```bash
curl -sS -X POST https://auth.eforge.xyz/api/admin/clients \
  -H "Content-Type: application/json" \
  -H "X-Admin-Api-Key: $ADMIN_API_KEY" \
  -d '{
    "name": "my-app-web",
    "redirect_uris": [
      "https://app.example.com/auth/callback",
      "http://localhost:5173/auth/callback"
    ],
    "skip_consent": true,
    "require_pkce": true
  }'
```

响应含 `clientSecret` **仅一次**。列表/详情永不回传 secret。

|------|------|
| `src/lib/cf-auth-oauth.ts` | PKCE、authorize URL、换 token、meta |

## 四、Issuer 与路径

| 项 | 值 |
|----|-----|
| Issuer / baseURL | `https://auth.eforge.xyz`（**无** `/api/auth` 后缀） |
| Authorize | `{issuer}/api/auth/oauth2/authorize` |
| Token | `{issuer}/api/auth/oauth2/token` |
| UserInfo | `{issuer}/api/auth/oauth2/userinfo` |
| AS metadata | `/.well-known/oauth-authorization-server` |

## 五、生产检查清单

- [ ] redirect_uri **精确**匹配（含 path，无尾斜杠漂移）  
- [ ] Google/GitHub 控制台 callback 仍是 **cf-auth** 的 `/api/auth/callback/*`，不是业务域名  
- [ ] `TRUSTED_ORIGINS` 含业务 origin  
- [ ] secret 只在服务端；前端只有 client_id + PKCE  
- [ ] 业务 smoke 与 `npm run smoke:prod`（auth 侧）通过
