## 三、API 一览

```text
GET    /api/admin/health
GET    /api/admin/clients
POST   /api/admin/clients
GET    /api/admin/clients/:clientId
PATCH  /api/admin/clients/:clientId
POST   /api/admin/clients/:clientId/rotate-secret
GET    /api/admin/users
GET    /api/admin/users/:userId/sessions
DELETE /api/admin/users/:userId/sessions
DELETE /api/admin/sessions/:sessionId
GET    /api/admin/audit
```

鉴权：

1. `X-Admin-Api-Key` 或 `Authorization: Bearer <ADMIN_API_KEY>`  
2. 或 Better Auth session 且 email/id ∈ 白名单  

未配置任何管理员 → **503**（避免全员可管）。

## 五、生产配置补充

```bash
# 平台管理员（示例）
npx wrangler secret put ADMIN_EMAILS   # you@eforge.xyz
npx wrangler secret put ADMIN_API_KEY  # 脚本用，足够长随机串

# 邮箱策略（P0-3）：参与端若只社交可关
# EMAIL_PASSWORD_ENABLED=false
# 管理登录若依赖邮箱密码，需保持 true 或改用社交登录后进 Admin
```

部署：`npm run deploy`（先 build frontend 再 wrangler）。

迁移：启动时 `applyAuthMigrations` 幂等创建 `admin_audit_log` / `rate_limit_log`。

## 七、lottery 接入复盘：仍建议优化点

| 点 | 说明 |
|----|------|
| TRUSTED_ORIGINS 手工 | 每加 RP 改 secret/env + redeploy；中期可配置表 |
