## 发现的 Bug（已修复）

### Bug 1: create-project.mjs seo-config.json 双重替换

**背景**：创建 cf-static 项目时，seo-config.json 的 siteName 被错误替换。

**根因**：
1. 代码先设置 `seoConfig.siteName = name`（如 "test-cf-static"）
2. 然后 `replaceInDir()` 对 .json 文件做文本替换 `"cf-static"` → `"test-cf-static"`
3. 导致 siteName 变为 `"test-test-cf-static"`

**修复**：将 seo-config.json 的 JSON 更新移到文本替换之后执行，覆盖可能被误替换的值。

**验证**：修复后 `siteName = "test-cf-static"`，正确。

### 误报 1: wrangler.jsonc 解析失败

测试脚本用 `JSON.parse()` 解析 wrangler.jsonc（含注释的 JSONC 格式），解析失败。
实际文件内容已正确替换（`"name": "test-cf-shop"`），是测试工具的问题。

### 误报 2: 残留模板名

grep 搜索 `"cf-shop"` 匹配了 `"test-cf-shop"`（已替换后的新名称）。
精确搜索（排除新名称子串）确认：**0 个未替换的原始模板名**。

## 部署脚本依赖链

```
00-init-project.sh
  ├─ 前置: check_cmd(node, npm, jq, openssl, curl)
  ├─ 输入: PROJECT_NAME (env/basename)
  └─ 输出: cred_save(GITHUB_REPO, PROJECT_NAME)

01-setup-turso.sh
  ├─ 前置: check_cmd(turso)
  ├─ 输入: cred_load(PROJECT_NAME) ← Step 00
  └─ 输出: cred_save(TURSO_URL, TURSO_TOKEN, DB_NAME, TURSO_LOCATION, GROUP_NAME)

02-setup-secrets.sh
  ├─ 输入: (无前置依赖)
  └─ 输出: cred_save(ADMIN_TOKEN, RATE_LIMIT_SALT, JWT_SECRET, CREDENTIALS_ENCRYPTION_KEY)

03-deploy-worker.sh
  ├─ 前置: check_env(CLOUDFLARE_API_TOKEN)
  ├─ 输入: cred_load(PROJECT_NAME ← 00, TURSO_URL ← 01, TURSO_TOKEN ← 01,
  │         ADMIN_TOKEN ← 02, RATE_LIMIT_SALT ← 02, JWT_SECRET ← 02, CREDENTIALS_ENCRYPTION_KEY ← 02)
  └─ 输出: cred_save(WORKER_NAME, BASE_URL, DEPLOY_MODE)

04-bind-domain.sh
  ├─ 前置: check_env(CLOUDFLARE_API_TOKEN), DOMAIN (env)
  ├─ 输入: cred_load(WORKER_NAME ← 03)
  └─ 输出: cred_save(DOMAIN, BASE_URL)

05-setup-turnstile.sh
  ├─ 前置: check_env(CLOUDFLARE_API_TOKEN)
  ├─ 输入: cred_load(PROJECT_NAME ← 00, WORKER_NAME ← 03, DOMAIN ← 04, TURSO_URL ← 01)
  └─ 输出: cred_save(TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEY)

06-setup-github.sh
  ├─ 前置: check_cmd(gh), gh_check
  ├─ 输入: cred_load(PROJECT_NAME ← 00, GITHUB_REPO ← 00, WORKER_NAME ← 03,
  │         DOMAIN ← 04, TURSO_URL ← 01, TURSO_TOKEN ← 01, BASE_URL ← 03/04,
  │         + 所有 secrets ← 02)
  └─ 输出: step_done(06-setup-github)
```
