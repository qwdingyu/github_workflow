# 脚本调用契约总索引

## 背景

脚本越来越多，如果只记在对话里，后续一定会丢上下文。所有脚本必须同时满足两个要求：

```text
1. 脚本文件开头有中文契约注释：用途、必填变量、可选变量、示例命令、风险边界。
2. 根目录 docs 有总索引：新项目不知道用哪个脚本时，先看本文。
```

本文不记录真实 token。所有示例里的 `<token>`、`<key>`、`<email>` 都必须由本地环境变量或临时命令传入，不能提交到 Git。

## 根目录 Cloudflare 脚本

### 1. Pages GitHub + 域名 + DNS

脚本：

```text
scripts/cloudflare/pages_github_domain_workflow.mjs
```

适用：

```text
Cloudflare Pages 项目
GitHub 自动部署
Pages custom domain
普通 DNS CNAME
```

最小命令：

```bash
CF_AUTH_EMAIL="<email>" \
CF_GLOBAL_API_KEY="<global-api-key>" \
CF_CUSTOM_DOMAIN="tool.eforge.xyz" \
rtk node ../scripts/cloudflare/pages_github_domain_workflow.mjs
```

常用变量：

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `CF_CUSTOM_DOMAIN` | 是 | 无 | 正式域名 |
| `CF_API_TOKEN` | 鉴权二选一 | 无 | Pages/DNS 都有权限时可用 |
| `CF_AUTH_EMAIL` + `CF_GLOBAL_API_KEY` | 鉴权二选一 | 无 | Global API Key 兜底 |
| `CF_DNS_API_TOKEN` | 否 | 复用主鉴权 | DNS 专用 token |
| `CF_ACCOUNT_ID` | 否 | 账号唯一时推导 | Cloudflare account id |
| `CF_ZONE_ID` | 否 | 从域名推导 zone 后查询 | Cloudflare zone id |
| `CF_PAGES_PROJECT` | 否 | GitHub repo 名 | Pages 项目名 |
| `CF_GITHUB_OWNER` | 否 | 从 git remote 推导 | GitHub owner |
| `CF_GITHUB_REPO` | 否 | 从 git remote 推导 | GitHub repo |
| `CF_DESTINATION_DIR` | 否 | `src` | Pages 输出目录 |
| `CF_DNS_PROXIED` | 否 | `false` | CNAME 是否橙云代理 |

关键规则：

```text
1. 不猜 <project>.pages.dev，必须读取 Cloudflare Pages 返回的 subdomain。
2. 首次 Pages custom domain 绑定建议 proxied=false。
3. Pages active 后，如果要 WAF 生效，再用 CF_DNS_PROXIED=true 切橙云代理。
4. 脚本不删除 Pages project、custom domain 或 DNS record。
```

### 2. Workers Custom Domain

脚本：

```text
scripts/cloudflare/workers_custom_domain_bind.mjs
```

适用：

```text
Cloudflare Workers
Workers Static Assets
Workers Custom Domains
```

直接绑定：

```bash
CF_AUTH_EMAIL="<email>" \
CF_GLOBAL_API_KEY="<global-api-key>" \
CF_WORKER_SERVICE="acctbox" \
CF_CUSTOM_DOMAIN="acctbox.eforge.xyz" \
rtk node scripts/cloudflare/workers_custom_domain_bind.mjs
```

从旧域名推导 Worker：

```bash
CF_AUTH_EMAIL="<email>" \
CF_GLOBAL_API_KEY="<global-api-key>" \
CF_SOURCE_CUSTOM_DOMAIN="ai.eforge.xyz" \
CF_CUSTOM_DOMAIN="auth.eforge.xyz" \
rtk node scripts/cloudflare/workers_custom_domain_bind.mjs
```

常用变量：

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `CF_CUSTOM_DOMAIN` | 是 | 无 | 要绑定的新域名 |
| `CF_WORKER_SERVICE` | 二选一 | 无 | Worker 服务名 |
| `CF_SOURCE_CUSTOM_DOMAIN` | 二选一 | 无 | 从已有绑定推导 Worker |
| `CF_API_TOKEN` | 鉴权二选一 | 无 | Cloudflare API Token |
| `CF_AUTH_EMAIL` + `CF_GLOBAL_API_KEY` | 鉴权二选一 | 无 | Global API Key 兜底 |
| `CF_ACCOUNT_ID` | 否 | 账号唯一时推导 | Cloudflare account id |
| `CF_ZONE_ID` | 否 | 从域名推导 zone 后查询 | Cloudflare zone id |
| `CF_WORKER_ENVIRONMENT` | 否 | `production` | Worker 环境 |
| `CF_DELETE_SOURCE_CUSTOM_DOMAIN` | 否 | `false` | 是否删除旧域名 |
| `CF_REPLACE_CONFIRM` | 删除时必填 | 无 | 防误删确认 |

关键规则：

```text
1. Workers Custom Domain 不是 Pages CNAME。
2. Cloudflare 会自动创建只读 AAAA 100:: 记录。
3. 默认只新增，不删除旧域名。
4. 删除旧域名必须显式确认。
```

### 3. Cloudflare 配置层安全基线

脚本：

```text
scripts/cloudflare/security_baseline.mjs
```

适用：

```text
Zone 级基础安全
WAF Custom Rules
危险路径阻断
管理路径 Challenge
可选 Zone Settings
```

预览：

```bash
CF_API_TOKEN="<token>" \
CF_CUSTOM_DOMAIN="acctbox.eforge.xyz" \
rtk node scripts/cloudflare/security_baseline.mjs
```

实际写入：

```bash
CF_API_TOKEN="<token>" \
CF_CUSTOM_DOMAIN="acctbox.eforge.xyz" \
CF_APPLY=true \
rtk node scripts/cloudflare/security_baseline.mjs
```

多域名合并写入：

```bash
CF_API_TOKEN="<token>" \
CF_TARGET_HOSTNAMES="acctbox.eforge.xyz,ai.eforge.xyz,tool.eforge.xyz,shop.eforge.xyz" \
CF_SECURITY_SCENARIO="app" \
CF_ENABLE_ZONE_SETTINGS=false \
CF_APPLY=true \
rtk node scripts/cloudflare/security_baseline.mjs
```

常用变量：

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `CF_CUSTOM_DOMAIN` | 二选一 | 无 | 单域名 |
| `CF_TARGET_HOSTNAMES` | 二选一 | 无 | 多域名，逗号分隔 |
| `CF_API_TOKEN` | 鉴权二选一 | 无 | Cloudflare API Token |
| `CF_AUTH_EMAIL` + `CF_GLOBAL_API_KEY` | 鉴权二选一 | 无 | Global API Key 兜底 |
| `CF_APPLY` | 否 | `false` | 是否真正写入 |
| `CF_SECURITY_SCENARIO` | 否 | `app` | `static` / `app` / `form` |
| `CF_ENABLE_ZONE_SETTINGS` | 否 | `true` | 是否写 Zone Settings |
| `CF_ENABLE_WAF_RULES` | 否 | `true` | 是否写 WAF |
| `CF_ENABLE_HEADER_TRANSFORM` | 否 | `false` | 是否写响应头 Transform Rule |
| `CF_BLOCK_STATIC_UNSAFE_METHODS` | 否 | `false` | 静态站是否只允许 GET/HEAD |
| `CF_ZONE_SETTINGS_REQUIRED` | 否 | `false` | Zone Settings 失败是否中断 |

关键规则：

```text
1. 默认只预览，CF_APPLY=true 才写入。
2. 同一 zone 多个域名应合并到同一套 WAF 规则，节省免费层配额。
3. 脚本只维护 cf_baseline_ 开头的规则，不覆盖人工规则。
4. WAF 不能替代业务鉴权、Turnstile、限流和幂等。
5. Pages 域名必须是 proxied=true，WAF 才会生效。
```

### 4. 静态资源安全头生成

脚本：

```text
scripts/cloudflare/write_security_headers.mjs
```

适用：

```text
Cloudflare Pages
Workers Static Assets
项目内 _headers 文件
```

命令：

```bash
CF_HEADERS_FILE="src/_headers" \
CF_HEADERS_SCENARIO="static" \
rtk node ../scripts/cloudflare/write_security_headers.mjs
```

常用变量：

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `CF_HEADERS_FILE` | 否 | `public/_headers` | 写入路径 |
| `CF_HEADERS_SCENARIO` | 否 | `app` | `static` / `app` |
| `CF_OVERWRITE_HEADERS` | 否 | `false` | 是否覆盖已有文件 |
| `CF_CONNECT_SRC` | 否 | `'self'` | CSP connect-src |
| `CF_IMG_SRC` | 否 | `'self',data:` | CSP img-src |
| `CF_SCRIPT_SRC` | 否 | `'self'` | CSP script-src |
| `CF_STYLE_SRC` | 否 | `'self'` | CSP style-src |

关键规则：

```text
1. 不需要 Cloudflare token。
2. 默认不覆盖已有 _headers。
3. CSP 应按项目实际资源调整，不要机械复制。
```

### 5. Cloudflare 权限探针

脚本：

```text
scripts/cloudflare/capability_probe.mjs
```

适用：

```text
检查 token 是否有 Pages / Workers Domains / DNS 权限。
```

命令：

```bash
CF_API_TOKEN="<token>" \
CF_ACCOUNT_ID="<account_id>" \
CF_ZONE_ID="<zone_id>" \
CF_PAGES_PROJECT="vibox-shop" \
rtk node scripts/cloudflare/capability_probe.mjs
```

常用变量：

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `CF_ACCOUNT_ID` | 是 | 无 | Cloudflare account id |
| `CF_ZONE_ID` | 是 | 无 | Cloudflare zone id |
| `CF_API_TOKEN` | 鉴权二选一 | 无 | Cloudflare API Token |
| `CF_AUTH_EMAIL` + `CF_GLOBAL_API_KEY` | 鉴权二选一 | 无 | Global API Key 兜底 |
| `CF_PAGES_PROJECT` | 否 | `vibox-shop` | 用于 deployments 检查 |

关键规则：

```text
1. 只读检查，不修改资源。
2. FAIL 不等于项目不可用，只说明当前凭据缺对应权限。
```

## AcctBox 项目脚本

路径：

```text
acctbox/scripts
```

这些脚本在 `acctbox` 项目根目录执行。

### 1. check

命令：

```bash
rtk npm run check
```

用途：

```text
本地静态结构检查，不访问 Cloudflare，不消耗库存。
```

### 2. verify

命令：

```bash
BASE_URL="https://acctbox.eforge.xyz" rtk npm run verify
```

用途：

```text
验证 HTTPS 和 /api/health，适合日常巡检。
```

常用变量：

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `BASE_URL` | 否 | workers.dev | 验证目标 |
| `RESOLVE_IP` | 否 | 无 | 指定边缘 IP 排障 |
| `VERIFY_ATTEMPTS` | 否 | `6` | 重试次数 |
| `VERIFY_INTERVAL_MS` | 否 | `5000` | 重试间隔 |

### 3. smoke

命令：

```bash
BASE_URL="https://acctbox.eforge.xyz" rtk npm run smoke
```

用途：

```text
验证完整发卡链路，会真实消耗一条 available 卡密。
```

规则：

```text
1. 日常巡检优先 verify。
2. smoke 只在需要证明写链路时运行。
3. 库存不足时 smoke 会失败，不代表服务不可用。
```

### 4. deploy:full

命令：

```bash
CLOUDFLARE_API_TOKEN="<token>" \
ACCTBOX_SEED_REMOTE=false \
BASE_URL="https://acctbox.mailforwdy.workers.dev" \
rtk npm run deploy:full
```

用途：

```text
D1 database_id 复用/创建
远程 migration
可选 seed
Worker deploy
可选绑定域名
最后 smoke
```

常用变量：

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `CLOUDFLARE_API_TOKEN` | 是 | 无 | Wrangler 远程操作 |
| `ACCTBOX_WORKER_NAME` | 否 | `acctbox` | Worker 名 |
| `ACCTBOX_D1_DATABASE` | 否 | `acctbox-db` | D1 数据库名 |
| `ACCTBOX_SEED_REMOTE` | 否 | `true` | 是否远程 seed |
| `ACCTBOX_BIND_DOMAIN` | 否 | `false` | 是否绑定正式域名 |
| `ACCTBOX_CUSTOM_DOMAIN` | 否 | `acctbox.eforge.xyz` | 正式域名 |
| `BASE_URL` | 否 | workers.dev | smoke 目标 |

风险：

```text
1. seed.sql 只能放演示数据。
2. deploy:full 最后会运行 smoke，可能消耗库存。
3. 生产项目应补只读 smoke，避免每次部署消耗真实库存。
```

## 新项目脚本选择顺序

```text
1. 纯静态 Pages：pages_github_domain_workflow -> write_security_headers -> security_baseline。
2. Workers 静态/API：wrangler deploy -> workers_custom_domain_bind -> security_baseline。
3. 带 D1 存储：migration/seed -> deploy -> verify -> smoke -> security_baseline。
4. 不确定 token 权限：先 capability_probe。
```

## 当前最佳实践摘要

```text
1. Pages 初始域名验证可用 DNS-only。
2. Pages active 后要接 WAF，必须切 proxied=true。
3. Workers Custom Domain 自动走 Cloudflare 代理层，WAF 可直接生效。
4. 同一 zone 多域名合并 WAF 规则，减少免费层规则占用。
5. 每个脚本新增变量时，必须同步改脚本头部注释和本文。
```
