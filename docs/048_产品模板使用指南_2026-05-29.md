## 一、模板清单

| 模板 | 目录 | 适用场景 | 复杂度 |
|------|------|---------|--------|
| **cf-form-kit** | `templates/cf-form-kit/` | 表单/信息收集/落地页 | 极低 |
| **cf-shop** | `templates/cf-shop/` | 卡密/数字商品发卡商城 | 高 |
| **cf-api** | `templates/cf-api/` | API 中间层/渠道聚合 | 中高 |
| **cf-tools** | `templates/cf-tools/` | 在线工具集/SaaS 工具站 | 中 |

## 二、快速开始（通用步骤）

### Step 1: 选择模板并复制

```bash
# 选择适合你业务的模板
TEMPLATE=cf-shop    # 或 cf-api / cf-tools / cf-form-kit
PROJECT=my-new-app

cp -R templates/$TEMPLATE ../$PROJECT
cd ../$PROJECT
git init
```

### Step 2: 基础配置（5 分钟）

```bash
npm install
```

修改以下文件：

| 文件 | 改什么 |
|------|--------|
| `package.json` | `name` 改为你的项目名 |
| `wrangler.jsonc` | `name` 改为 Worker 名，`APP_ORIGIN` 改为你的域名 |
| `src/config.ts` | 业务配置（模板内有详细注释） |
| `public/index.html` | 品牌元素（标题/Logo/颜色） |

### Step 3: 创建数据库

```bash
# 方式 A: Turso（推荐，Free 9GB）
npx turso db create my-new-app
npx turso db show my-new-app  # 获取 URL 和 Token

# 方式 B: D1（极轻量场景）
npx wrangler d1 create my-new-app-db
# 将输出的 database_id 写入 wrangler.jsonc
```

### Step 4: 初始化数据库

```bash
# Turso
TURSO_URL="libsql://xxx.turso.io" TURSO_TOKEN="xxx" node scripts/migrate.mjs

# D1
npx wrangler d1 migrations apply my-new-app-db --remote
```

### Step 5: 配置 Secrets

```bash
# 必须
npx wrangler secret put ADMIN_TOKEN
# 输入一个强随机字符串

# 可选（按需）
npx wrangler secret put TURNSTILE_SECRET_KEY
npx wrangler secret put RATE_LIMIT_SALT
```

### Step 6: 本地验证

```bash
npm run dev
# 另开终端
npm run smoke:readonly
```

### Step 7: 部署

```bash
npm run deploy
```

### Step 8: 绑定域名（可选）

```bash
# 修改 wrangler.jsonc 添加 routes 配置
# 或通过 Cloudflare Dashboard 绑定
```

## 三、各模板定制指南

### cf-shop（发卡商城）

**核心配置文件**：`src/config.ts`

```ts
export const SHOP_CONFIG = {
  name: "我的商城",
  currency: "CNY",
  // 支付方式：alipay（支付宝当面付）/ offline（线下）
  paymentMethods: ["offline"],
  // 订单过期时间（分钟）
  orderExpireMinutes: 30,
};
```

**添加支付渠道**：在 `src/services/payments/` 目录下新建 Provider 文件，实现 `PaymentProvider` 接口并注册到 `registry.ts`。

**添加邮件通知**：在 `src/config.ts` 中配置 Resend API Key，启用邮件模板。

### cf-api（API 中间层）

**核心配置文件**：`src/config.ts`

```ts
export const API_CONFIG = {
  name: "我的 API 服务",
  // 支持的服务类型
  serviceTypes: ["sms", "email"],
  // 默认超时（秒）
  defaultTimeout: 300,
};
```

**添加渠道适配器**：在 `src/channels/` 目录下新建适配器文件，实现 `ChannelAdapter` 接口并注册到 `manager.ts`。

**添加服务处理器**：在 `src/services/handlers/` 目录下新建 Handler，实现 `ServiceHandler` 接口。

### cf-tools（工具集）

**核心配置文件**：`src/config.ts`

```ts
export const TOOLS_CONFIG = {
  name: "我的工具箱",
  // 是否启用用户注册
  enableRegistration: true,
  // JWT 有效期（秒）
  jwtExpiry: 86400,
};
```

**添加工具**：在 `src/services/tools/` 目录下新建工具文件，实现 `ToolDriver` 接口并注册到 `registry.ts`。参见 `example-tool.ts` 示例。

## 五、Cloudflare Free 套餐注意事项

| 限制 | 应对策略 |
|------|---------|
| 10 万请求/天 | Cache API 缓存（不计入配额）+ Edge Cache |
| 10ms CPU/请求 | Hono 轻量框架 + Isolate 级连接复用 |
| 无 Cron Trigger | GHA 定时调 API / 惰性清理 |
| 1MB Bundle | 精简依赖，避免大库 |
| 无 Durable Objects | 用 DB 原子操作替代分布式锁 |

## 六、常见问题

**Q: 模板更新后如何同步？**
A: 不建议自动同步。手动对比 `templates/cf-shop/` 的变更，按需 cherry-pick。cf-core 的更新通过 npm 版本管理。

**Q: 可以把模板放到独立仓库吗？**
A: 可以。将 `@eforge/cf-core` 发布到 GitHub Packages 后，package.json 中的 `file:` 改为 npm 包名即可。

**Q: 多个产品共用一个 Turso 数据库还是各自独立？**
A: 强烈建议各自独立。每个产品一个 Turso 数据库，避免数据耦合，便于独立备份和迁移。
