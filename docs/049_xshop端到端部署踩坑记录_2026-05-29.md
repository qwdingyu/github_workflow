## 二、踩坑清单（共 9 个，全部已修复）

### 第一轮发现的 Bug

#### 坑 1: bash 间接变量长度语法错误 🔴致命

**文件**: `shared.sh` → `check_env()`
**现象**: `${#!name}` → `bad substitution`
**原因**: bash 不支持 `${#!name}` 组合语法
**修复**:
```bash
# ❌ 错误
log_ok "$name 已设置 (${#!name} 字符)"
# ✅ 正确
local val="${!name:-}"
log_ok "$name 已设置 (${#val} 字符)"
```

#### 坑 2: Turso API 组织名字段名大小写 🔴致命

**文件**: `shared.sh` → `turso_get_org()`
**现象**: jq 报错 `Cannot index number with string "username"`
**原因**: Turso API 返回 `{slug: "qwsky"}`（小写），脚本用 `.[0].Name`（大写）；`/whoami` 端点返回 404 不存在
**修复**:
```bash
# ❌ 错误
_turso_org=$(echo "$resp" | jq -r '.[0].Name // empty')
# ✅ 正确
_turso_org=$(echo "$resp" | jq -r '.[0].slug // .[0].name // empty')
```

#### 坑 3: Turso Token 创建 API 返回 404 🔴致命

**文件**: `01-setup-turso.sh` → Step 3
**现象**: `POST /databases/{db}/tokens` → 404
**原因**: Turso REST API Token 端点不稳定
**修复**: 改用 `turso` CLI + `HOMEBREW_NO_AUTO_UPDATE=1` + `timeout 30`
```bash
# ❌ 错误（API 不存在）
RESULT=$(turso_api POST ".../tokens" '...')
# ✅ 正确
export HOMEBREW_NO_AUTO_UPDATE=1
TURSO_TOKEN=$(timeout 30 turso db tokens create "$DB_NAME" 2>/dev/null | grep -E '^eyJ' | head -1)
```

#### 坑 4: Worker URL 子域名不匹配 🟠高

**文件**: `03-deploy-worker.sh` → Step 3
**现象**: 冒烟测试 URL 错误
**原因**: 硬编码 `${WORKER_NAME}.workers.dev`，实际是 `${WORKER_NAME}.${ACCOUNT_SUBDOMAIN}.workers.dev`
**修复**: 从 `wrangler deploy` 输出 grep 实际 URL

#### 坑 5: wrangler.jsonc 注释中旧变量名 🟡低

**文件**: 三个模板的 `wrangler.jsonc`
**现象**: 注释列出 `ENCRYPTION_KEY`/`SMTP_HOST` 等已废弃变量
**修复**: 替换为正确的变量清单（`CREDENTIALS_ENCRYPTION_KEY`/`RESEND_API_KEY` 等）

### 第二轮发现的 Bug（删除重跑时发现）

#### 坑 6: turso CLI 触发 Homebrew 自动更新导致超时 🟠高

**文件**: `01-setup-turso.sh` → Step 3
**现象**: `turso db tokens create` 卡住 120s+
**原因**: turso CLI 自动触发 `brew upgrade`，从境内下载极慢
**修复**: 添加 `export HOMEBREW_NO_AUTO_UPDATE=1` + `timeout 30` + `grep -E '^eyJ'` 过滤有效 Token

#### 坑 7: shared.sh 中 log_ok 污染 stdout 捕获 🔴致命

**文件**: `shared.sh` → `turso_get_org()` 和 `cf_get_account_id()`
**现象**: Step 01 在 "Step 2/4: 创建数据库" 静默退出（exit 1 无错误信息）
**原因**: `ORG=$(turso_get_org)` 捕获了 `log_ok "Turso 组织: qwsky"` 的 stdout 输出，导致 `ORG` 变量值为 `[OK]    Turso 组织: qwsky\nqwsky`（两行），后续 API 路径变成 `/organizations/[OK]    Turso...`
**修复**: 所有在"返回值函数"中的 log 输出重定向到 stderr
```bash
# ❌ 错误（log_ok 输出到 stdout，污染捕获）
log_ok "Turso 组织: $_turso_org"
echo "$_turso_org"
# ✅ 正确（log_ok 输出到 stderr，不污染）
log_ok "Turso 组织: $_turso_org" >&2
echo "$_turso_org"
```
**教训**: **bash 中任何通过 `echo` 返回值的函数，内部的 log/print 必须重定向到 stderr**

#### 坑 8: migrate.mjs 未去除 SQL 注释 🟠高

**文件**: `scripts/migrate.mjs`
**现象**: Turso 返回 `SERVER_ERROR: HTTP 502`
**原因**: SQL 文件中的 `--` 注释行未被去除，整个注释块 + CREATE TABLE 被当作一条语句发送到 Turso
**修复**: 在 `split(";")` 前先过滤 `--` 开头的行
```js
// ❌ 错误
const statements = sql.split(";").map(s => s.trim()).filter(s => s.length > 0);
// ✅ 正确
const statements = sql
  .split("\n")
  .filter((line) => !line.trim().startsWith("--"))
  .join("\n")
  .split(";")
  .map((s) => s.trim())
  .filter((s) => s.length > 0);
```

#### 坑 9: gh CLI 到 GitHub 网络慢 🟡低

**文件**: `06-setup-github.sh`
**现象**: `gh secret set` 每个 Secret 5-10s，总计超时
**修复**: `gh_set_secret`/`gh_set_variable` 添加 `timeout 30` 容错，超时不中断

## 六、经验总结（9 条铁律）

1. **bash 函数返回值陷阱**：任何用 `echo` 返回值的函数，内部 `log_*` 必须 `>&2`
2. **Turso CLI 优先**：Token 创建/数据库管理用 CLI，REST API 端点不稳定
3. **Homebrew 自动更新**：所有 CLI 工具前加 `HOMEBREW_NO_AUTO_UPDATE=1`
4. **wrangler deploy 输出要捕获**：URL 包含账户子域名，不能硬编码
5. **bash 间接引用**：`${!name}` 取值可以，`${#!name}` 取长度不行
6. **SQL 迁移必须去注释**：libsql HTTP 模式不支持 `--` 注释行混在语句中
7. **网络超时要有 timeout**：curl/gh 都加 `--max-time`/`timeout`，避免卡死
8. **幂等设计**：数据库已存在→复用，Token 已有→复用，Git 仓库已有→复用
9. **冒烟测试要容错**：网络超时算 warning 不算 failure，CF API 验证是权威来源
