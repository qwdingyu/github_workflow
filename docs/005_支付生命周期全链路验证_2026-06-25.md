# 005 支付生命周期全链路验证

> 本文以当前代码为准，记录 cf-shop 支付链路的真实实现、前端调用方式、状态机与测试覆盖。
> 核对时间：2026-06-25

---

## 1. 核心结论（与真实代码一致）

| 维度 | 结论 |
|------|------|
| 统一入口 | `POST /api/pay/unified`，前端自动走此接口 |
| 模式枚举 | `mode: online | offline | balance` |
| 线下确认 | `POST /api/pay/offline/confirm`，记录 `paymentRef = "last4:<payRefLast4>"` |
| 状态轮询 | `GET /api/pay/status/:orderId?token=<orderToken>` |
| 自动过期 | 轮询时调用 `checkAndExpireOrder`，过期自动转 `expired` 并释放库存 |
| 管理员确认 | `POST /admin/orders/:id/mark-paid`，调用 `markPaidAndIssue` |
| 前端调用 | `frontend/src/api/index.ts` 的 `unifiedPay / getPayStatus / confirmOfflinePay` |

## 2. 后端真实实现（已核对代码）

### 2.1 统一下单：`templates/cf-shop/src/routes/pay.ts`

- `POST /pay/unified`
- 先校验 Turnstile、限流、幂等键
- 查商品、校验库存、quote 优惠码
- 软锁定卡密：`lockFulfillmentInventory(db, orderId, product.id, expiresAt)`

**三条分支：**

1. **余额支付**：`balancePayment=true`
   - 直接走 `handleBalancePayment`
   - 成功返回 `{ mode: "balance", status: "issued", delivery: {...} }`

2. **线上支付**：有可用 Provider
   - 调用 `provider.createPayment`
   - 返回 `{ mode: "online", qrcode, redirectUrl }`
   - 回调：`/pay/callback/:provider` → 验签 → 金额校验 → `markPaidAndIssue`

3. **线下支付**：线上失败或无 Provider
   - 调用 `createOfflineOrder`
   - 返回 `{ mode: "offline", offlineNoteCode, wechatQr, alipayQr, offlineHint }`
   - 用户确认：`/pay/offline/confirm`

### 2.2 订单服务：`templates/cf-shop/src/services/order-service.ts`

- `checkAndExpireOrder`：条件 UPDATE，只在 `pending/paid` 时过期
- `markPaidAndIssue`：统一支付回调 + 管理员确认的发卡逻辑
  - pending → paid（原子 UPDATE + RETURNING）
  - 并发保护：已发卡直接返回已有卡密
  - coupon 消耗放在发卡后，防止管理员拒绝后无法回退

### 2.3 管理端：`templates/cf-shop/src/routes/admin.ts`

- `POST /admin/orders/:id/mark-paid` → `markPaidAndIssue`
- `POST /admin/orders/:id/cancel` → `cancelOrder`
- 审计日志：`writeAdminAudit`

## 3. 前端真实调用（已核对代码）

### 3.1 API 封装：`templates/cf-shop/frontend/src/api/index.ts`

```ts
// 统一下单
export function unifiedPay(payload: {
  productId: string
  buyerEmail: string
  couponCode?: string
  campaignCode?: string
  referralCode?: string
  turnstileToken?: string
  balancePayment?: boolean
}): Promise<{
  mode: 'online' | 'offline' | 'balance'
  provider?: string
  orderId: string
  orderNo: string
  orderToken: string
  amountCents: number
  currency: string
  qrcode?: string
  redirectUrl?: string
  offlineNoteCode?: string
  wechatQr?: string
  alipayQr?: string
  offlineHint?: string
  expiresAt?: string
  expireMinutes?: number
  delivery?: Delivery
}>

// 轮询支付状态
export function getPayStatus(orderId: string, orderToken: string): Promise<{
  orderId: string
  orderNo: string
  status: string
  delivery?: { accountLabel: string; deliverySecret: string; deliveryNote: string }
}>

// 线下支付确认
export function confirmOfflinePay(payload: {
  orderId: string
  orderToken: string
  payRefLast4: string
}): Promise<{ confirmed: boolean }>
```

### 3.2 线下支付 composable：`templates/cf-shop/frontend/src/composables/useOfflinePayment.ts`

- 状态：`wechatQr / alipayQr / offlineNoteCode / offlineHint / offlineExpiresAt`
- 确认逻辑：校验 `refLast4` 为 4 位 → 调用 `confirmOfflinePay` → 启动轮询
- 重置：`resetOfflinePayment`

### 3.3 前端类型定义：`templates/cf-shop/frontend/src/types/index.ts`

- `Order` 包含 `delivery?: Delivery`
- `Delivery` 包含 `accountLabel / deliverySecret / deliveryNote`
- `UnifiedPayData` 使用 `method`（与后端 `mode` 不一致，建议统一为 `mode`）

## 4. 状态机（真实代码）

```
pending
  ├─ 余额支付成功 → issued
  ├─ 线上支付回调成功 → issued
  ├─ 线下确认成功 → paid → issued
  ├─ 过期 → expired
  └─ 发卡失败（余额）→ failed
```

## 6. 与旧文档的差异修正

| 旧文档描述 | 真实代码 | 修正 |
|------------|----------|------|
| `UnifiedPayData.method` | 实际返回 `mode` | 统一为 `mode` |
| `paymentRef = "last4:1234..."` | 实际为 `last4:${payRefLast4}` | 无省略号 |
| 线下支付先改 paid 再发卡 | 回调层只更新 `paidAt + paymentRef`，发卡由 `markPaidAndIssue` 收敛 | 避免状态语义混乱 |
| 前端轮询未处理过期 | `/pay/status` 内调用 `checkAndExpireOrder` | 过期自动转 `expired` |
