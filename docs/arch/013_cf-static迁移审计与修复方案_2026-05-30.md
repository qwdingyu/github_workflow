# cf-static 迁移审计报告与修复方案

> **审计日期**: 2026-05-30  
> **审计范围**: templates/cf-static/ 迁移到 11ty 的完整审计  
> **优先级**: P0 级（阻塞性问题）

---

## 执行摘要

cf-static 模板迁移到 11ty 的过程中存在**三套模板体系并行、互不兼容**的致命问题。数据层（JSON）设计良好，但模板层（HTML）和构建层（11ty 配置）完全脱节，导致 11ty 实际不控制页面生成。

**核心结论**: 需要统一模板引擎为 Nunjucks，让 11ty Data Cascade 真正工作，然后删除 981 行的 `generate-seo-pages.mjs`。

---

## 一、致命问题（P0 - 必须立即修复）

### 致命问题 #1：模板体系三套并行，互不兼容

| 体系 | 文件 | 模板语法 | 被谁使用 |
|------|------|---------|---------|
| Nunjucks 布局 | `_layouts/base.njk` | `{{ title }}`、`{% if %}` | **无人使用** — 11ty 没触发 Data Cascade |
| Mustache 模板 | `templates/tool.html`、`post.html`、`doc.html` | `{{TITLE}}`、`{{SITE_NAME}}` | `generate-seo-pages.mjs` 手动字符串替换 |
| 手写脚本 | `generate-seo-pages.mjs` (981 行) | 无模板引擎 | 直接 `fs.writeFileSync` 输出 HTML |

**根本原因**: 三套体系互相隔离，11ty 配置虽然存在，但实际产出不为 11ty 所控。这就是 `npx eleventy --dryrun` 输出 0 文件的根本原因。

### 致命问题 #2：FAQ 字段命名不一致

| 工具 | FAQ 字段名 |
|------|-----------|
| base64-decode.json | `q` / `a` |
| json-formatter.json | `q` / `a` |
| md5-generator.json | `q` / `a` |
| regex-tester.json | `q` / `a` |
| timestamp-converter.json | `q` / `a` |
| url-encode-decode.json | `q` / `a` |
| uuid-generator.json | `q` / `a` |
| html-escape.json | `q` / `a` |
| **income-tax-calculator.json** | **`question` / `answer`** |
| **social-insurance-calculator.json** | **`question` / `answer`** |

**影响**: 财务计算器使用了不同的字段名，而 `generate-seo-pages.mjs` 第 166 行用 `item.q` 和 `item.a` 读取——财务计算器的 FAQ 在 Schema.org 中会输出 `undefined`。

## 二、严重问题（P1 - 影响 SEO 和用户体验）

### 严重问题 #3：tool.html 模板是"一刀切"的通用壳

`templates/tool.html` 第 78 行生成的 `TOOL_CONTENT` 对所有工具都一样：一个 textarea 输入 + 一个 textarea 输出 + 三个按钮。

但 `income-tax-calculator.js` 是一个完全自定义的表单（月收入、五险一金、专项附加扣除复选框、年终奖），根本不需要 textarea。`social-insurance-calculator.js` 同理（城市下拉、公积金比例滑块）。

**这个通用模板对财务计算器完全不适用。**

### 严重问题 #4：public/ 目录不应存在于源码中

`public/index.html`、`public/tools/*.html`、`public/blog/`、`public/docs/` 全部是构建产物，不应该提交到 Git。

**正确做法**:
- `public/` 只放静态资源（favicon、robots.txt）
- 构建输出放到 `_site/`（11ty 默认输出目录），加入 `.gitignore`

---

## 三、中等问题（影响可维护性）

### 中等问题 #5：模板 HTML 大量重复

`tool.html`、`post.html`、`doc.html` 三个模板各自包含完整的 `<!DOCTYPE html>`、`<head>`、`<header>`、`<footer>`——重复代码约 40 行 × 3 = 120 行。应该提取为 `_includes/` 下的 partials。

### 中等问题 #6：_layouts/base.njk 和 _includes/ 完全废弃

- `_layouts/base.njk` 写得不错，但从未被任何内容文件引用
- `_includes/` 目录为空

## 八、修复实施方案

### 阶段一：P0 修复（统一模板引擎）

#### 步骤 1：修复 .eleventy.js 配置

```javascript
// .eleventy.js
module.exports = function(eleventyConfig) {
  // 配置输入输出目录
  eleventyConfig.addGlobalData("layout", "base.njk");
  
  // 配置数据目录（11ty 自动加载 _data/ 下的 JSON）
  eleventyConfig.addPassthroughCopy("public");
  
  return {
    dir: {
      input: "src",
      output: "_site",
      includes: "_includes",
      layouts: "_includes/layouts"
    }
  };
};
```

#### 步骤 2：统一 FAQ 字段名

将所有 `tools/*.json` 中的 `q` / `a` 改为 `question` / `answer`。

#### 步骤 3：提取公共布局为 partials

创建以下文件：
- `src/_includes/layouts/base.njk`
- `src/_includes/partials/header.njk`
- `src/_includes/partials/footer.njk`

### 阶段二：P1 修复（SEO 优化）

#### 步骤 4：为财务计算器创建专用模板

创建 `src/_includes/layouts/calculator.njk`，专门用于财务计算器。

#### 步骤 5：清理 public/ 中的构建产物

```bash
rm -rf public/tools public/posts public/docs public/index.html
echo "public/tools/" >> .gitignore
echo "public/posts/" >> .gitignore
echo "public/docs/" >> .gitignore
echo "public/index.html" >> .gitignore
echo "_site/" >> .gitignore
```

### 阶段三：P2 修复（体验优化）

#### 步骤 6：补充缺失的工具 JS

为 8 个工具补充前端 JS 文件到 `public/assets/js/`。

#### 步骤 7：填充 styles.css

从现有的 `public/css/style.css` 迁移并优化。

#### 步骤 8：替换 seo-config.json 占位符

```json
{
  "siteName": "在线开发工具",
  "siteUrl": "https://devtools.online",
  "twitterHandle": "@devtools_online",
  "analyticsId": "G-XXXXXXXXXX"
}
```

## 九、总结

**一句话总结**: 数据层（JSON）设计得很好，模板层（HTML）和构建层（11ty 配置）完全脱节。需要把 Mustache 模板全部重写为 Nunjucks 布局 + partials，让 11ty 接管页面生成，然后就可以删除 981 行的 `generate-seo-pages.mjs`。

**预期效果**:
- 统一模板引擎后，维护成本大幅降低
- 11ty Data Cascade 真正工作后，SEO 结构化数据自动生效
- 删除 981 行手写脚本，减少维护负担
