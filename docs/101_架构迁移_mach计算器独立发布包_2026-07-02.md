# 架构迁移：mach 计算器合并为独立 npm 发布包

> 日期：2026-07-02
> 范围：`packages/mach-calculators`、`packages/mach-formulas`
> 结果：迁移到 `/Users/dingyuwang/0-X/2-node/mach-calculators`

## 背景

原 monorepo 中存在两个数控加工相关包：

- `packages/mach-formulas`：数控加工公式库。
- `packages/mach-calculators`：计算器 schema、renderer 和公式适配层。

两者代码量不大，且 `mach-calculators` 是 `mach-formulas` 的上层薄封装。继续维护两个独立 npm 包会引入版本同步、发布顺序和依赖治理成本。

## 决策

将两个包合并为一个独立发布包：

```text
@usethink/mach-calculators
```

新位置：

```text
/Users/dingyuwang/0-X/2-node/mach-calculators
```

公开入口：

- `@usethink/mach-calculators`：统一入口。
- `@usethink/mach-calculators/formulas`：公式库。
- `@usethink/mach-calculators/schema`：计算器 schema。
- `@usethink/mach-calculators/adapters`：表单输入到公式输入的适配层。

## 发布排查结论

`@usethink/cf-core` 可以继续使用 `@usethink/publish-toolkit`，但不能把该流程无条件复制到本包：

- `@usethink/publish-toolkit@0.1.8` 发布阶段会优先检测并执行 `pnpm publish`。
- `cf-core` 已配置 pnpm v11 的 `onlyBuiltDependencies[]=esbuild`，所以它的 `pnpm publish` 不会被 `ERR_PNPM_IGNORED_BUILDS` 阻断。
- 本包按用户要求使用 npm 发布，保留 publish-toolkit 会把 GitHub Actions 带回 pnpm 路径。
- 首次创建 `@usethink/mach-calculators` 时，GitHub Actions token 返回过 npm E404；本机 `iusethink` npm owner 登录态可以成功创建并发布。该 E404 属于 token/组织新包创建权限问题，不是包内容错误。
