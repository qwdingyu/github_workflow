| 类别 | 规则数 | 覆盖范围 |
|------|--------|---------|
| **GEO** | 35 | AI 引用密度、表格缺失、FAQ 结构、品牌实体、统计引用、问题式标题 |
| **SEO** | 32 | Title 长度、Meta Description、H1/H2 层级、关键词密度、内链外链、canonical |
| **Content Quality** | 14 | 可读性、段落长度、首句前置、重复内容、翻译完整性 |
| **Technical** | 8 | 断链、图片缺失、HTTP 链接、草稿泄漏、trailing slash |
| **i18n** | 3 | 翻译对缺失、locale 缺失、hreflang x-default |

#### 杀手锏：自主 Lint-Fix 循环

```
npx geo-lint --format=json
    ↓
AI Agent 读取结构化违规
    ↓
自动修复内容文件
    ↓
重新 lint
    ↓
直到干净或 5 轮耗尽
```

**geo-lint-fixer Agent 设计：**
- 接收内容 slug + 违规列表
- 解析 slug → 文件系统路径
- 按 severity 排序（error 优先）
- 应用 suggestion 字段中的修复策略
- 保留作者声音，不重写
- Human Escalation 规则：不伪造统计数据、不发明图片、不创建不存在的链接

### 3.1 从"写代码"到"写 Skill"

| 工具 | 用户量级 | 核心机制 |

### 3.2 开源 GEO 项目的三种 AI 化路径

#### 路径 A：Auriti-Labs — Agent 团队模式

```
用户说："帮我优化这个站点的 GEO"
    ↓
Claude Code 加载 geo-optimizer-skill
    ↓
编排器 (orchestrator) 启动
    ↓
分发任务给 12 个专用 Agent：
  - 引擎架构师 → 设计审计方案
  - QA 验证器 → 验证结果
  - 安全审查 → 检查隐私合规
  - WordPress 连接器 → 如果目标是 WP 站点
  - 仪表盘 UI → 生成报告界面
  - 平台 API → 对接 SaaS
    ↓
输出完整 GEO 优化方案
```

**优势：** 分工明确，可扩展，专业度高
**劣势：** 复杂度高，维护成本高

#### 路径 B：IJONIS — Linter + Fixer 模式

```
用户说："检查我的博客内容 GEO 合规性"
    ↓
Claude Code 加载 geo-lint skill
    ↓
npx geo-lint --format=json
    ↓
返回 92 条规则的违规列表
    ↓
geo-lint-fixer Agent 自动修复
    ↓
5 轮循环直到干净
    ↓
输出修复报告
```

**优势：** 简单直接，确定性高，易于集成
**劣势：** 仅限内容层面，不覆盖技术 SEO

#### 路径 C：madeburo — 框架插件模式

```
用户在 Next.js 项目中：
    npm install geo-ai-next
    ↓
导入中间件
    ↓
自动生成 llms.txt + robots.txt 规则
    ↓
SEO 信号注入到每个页面
```

**优势：** 开发者友好，零配置，框架原生
**劣势：** 需要为每个框架写适配器

### 3.3 我们的选择：混合模式

SEO Guardian 应该走 **A + B + C 的混合路线**：

```
Layer 1: GEO 规则引擎（借鉴 IJONIS 的 92 条规则 + Auriti 的 8 维度）
    ↓
Layer 2: Claude Code Skill + Agent（借鉴 Auriti 的 Agent 团队 + IJONIS 的 Fixer）
    ↓
Layer 3: Cloudflare Workers SaaS（我们已有的优势）
    ↓
Layer 4: 框架插件（借鉴 madeburo 的多框架策略）
```

## 八、总结：2026 年的 GEO 战场规则

### 8.1 三条铁律

1. **没有 llms.txt 支持的 GEO 工具 = 不完整**
   - OpenAI、Google、Perplexity 都在用 llms.txt
   - 2026 年 H2 将成为 AI 搜索的事实标准
   - 不做 llms.txt = 不做 GEO

2. **不能被 AI 编程工具调用的产品 = 不存在**
   - Claude Code / Cursor / Copilot 用户正在用 AI 工作
   - Skill + MCP + Agent 是新的分发渠道
   - 传统"下载 → 安装 → 使用"的路径已过时

3. **只能发现问题不能自动修复的工具 = 半成品**
   - IJONIS 证明了 lint-fix 循环的可行性
   - 用户要的是"帮我搞定"，不是"告诉我哪里错了"
   - AI Agent 自动修复是 2026 年的标配

### 8.2 我们的优势与劣势

| 优势 | 劣势 |
|------|------|
| Cloudflare Free 生态 ($0 成本) | GEO 核心功能严重缺失 |
| 已有完整的 SaaS 框架 | 没有 AI Skill / Agent |
| Workers AI 原生集成 | 不支持 llms.txt |
| 异步队列 + Cron 架构 | 不支持多框架 |
| 周报 + 趋势追踪 | 没有 MCP / CLI / Docker |
| Turso 数据库 (8GB Free) | 没有开源社区 |

### 8.3 一句话战略

> **用开源 GEO 规则引擎 + Claude Code Skill + MCP 建立开发者生态，用 Cloudflare SaaS + AI 扫描建立商业收入，成为"AI 时代第一个开发者友好的 GEO 平台"。**
