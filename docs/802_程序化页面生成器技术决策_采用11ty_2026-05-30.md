## 决策摘要

**采用 11ty (Eleventy) 作为静态站点生成器，替代自定义的 generate-seo-pages.mjs 脚本。**

**理由**：不重复造轮子，采用成熟、稳定、官方支持的开源方案。

---

## 背景

### 用户需求

构建一个程序化页面生成系统，支持：
- 从关键词数据批量生成 1000+ SEO 页面
- 部署到 Cloudflare Pages（静态托管）
- 自动生成 sitemap.xml、robots.txt、llms.txt
- 完整的 SEO 标签（Schema.org、OG、Twitter Card）

### 当前方案

cf-static 模板使用自定义的 `generate-seo-pages.mjs` 脚本：
- 从 JSON 配置生成 HTML
- 包含完整 SEO 标签
- 支持工具/博客/文档三种内容类型

### 发现的问题

经过深度分析，发现**我们在重复发明轮子**：

1. **自定义脚本的局限性**
   - 只能处理三种硬编码的内容类型
   - 每个工具需要单独的 JSON + JS 文件
   - 无法从关键词数据批量生成 1000 个页面
   - 需要自己实现所有 SEO 功能

2. **已有成熟方案**
   - 11ty (Eleventy)：JavaScript 生态，10+ 年历史，官方完全支持 Cloudflare Pages
   - Hugo：Go 生态，极快构建速度，官方支持 Cloudflare Pages
   - Astro：已移除 Cloudflare Pages 支持（仅支持 Workers）

- ⚠️ 学习成本中等（1-2周）

## 决策

### 采用方案：11ty (Eleventy)

**理由**：

1. **不重复造轮子**
   - 11ty 已经完美解决了程序化生成的所有问题
   - Data Cascade + Pagination 机制专为批量生成设计
   - 大型插件生态（RSS、Sitemap、SEO 等）

2. **官方完全支持**
   - Cloudflare Pages 官方完全支持（11ty 和 Cloudflare 双方官方支持）
   - 遇到问题有官方文档和社区帮助

3. **成熟稳定**
   - 10+ 年历史，生产环境验证
   - 大型社区，活跃维护

4. **JavaScript 生态**
   - 与我们的技术栈匹配（JavaScript/TypeScript）
   - 无需学习新语言

5. **部署流程相同**
   - `npm run build` → `_site` → `wrangler pages deploy`
   - 与现有部署流程完全兼容

6. **社区支持**
   - 大型社区，Stack Overflow 有大量问答
   - 遇到问题有社区帮助

### 保留的组件

| 组件 | 状态 | 说明 |
|------|------|------|
| **cf-core** | ✅ 保留 | Workers 共享内核，与静态生成无关 |
| **cf-shop** | ✅ 保留 | Workers 模板（发卡商城） |
| **cf-api** | ✅ 保留 | Workers 模板（API 中转站） |
| **cf-tools** | ✅ 保留 | Workers 模板（工具站） |
| **cf-form** | ✅ 保留 | Workers 模板（表单收集） |
| **部署脚本** | ✅ 保留 | one-click.sh 部署流程不变 |
| **所有基础设施工作** | ✅ 保留 | Cloudflare 集成、Turso、KV 等 |

### 改变的组件

| 组件 | 当前状态 | 改为 |
|------|---------|------|
| **cf-static 的 generate-seo-pages.mjs** | 自定义脚本 | **11ty** |
| **cf-static 的架构** | 自定义架构 | **11ty 架构** |
| **部署流程** | `npm run build` → `wrangler pages deploy` | **相同** |

## 实施计划

### Phase 1：初始化 11ty 项目（1-2天）

**目标**：将 cf-static 迁移到 11ty

**具体步骤**：

1. **初始化 11ty 项目**
   ```bash
   cd templates/cf-static
   npm init -y
   npm install @11ty/eleventy --save-dev
   ```

2. **配置 11ty**
   ```javascript
   // .eleventy.js
   module.exports = function(eleventyConfig) {
     // 配置数据目录
     eleventyConfig.addDataExtension("json", contents => JSON.parse(contents));
     
     // 配置输出目录
     eleventyConfig.setTemplateFormats(["html", "md", "njk"]);
     
     // 添加短代码
     eleventyConfig.addShortcode("year", () => `${new Date().getFullYear()}`);
     
     return {
       dir: {
         input: "src",
         output: "_site",
         data: "data",
         layouts: "layouts"
       }
     };
   };
   ```

3. **配置构建脚本**
   ```json
   // package.json
   {
     "scripts": {
       "build": "eleventy",
       "dev": "eleventy --serve",
       "deploy": "wrangler pages deploy _site"
     }
   }
   ```

**预期工作量**：1-2天

### Phase 2：迁移内容到 11ty（3-5天）

**目标**：将现有内容迁移到 11ty 架构

**具体步骤**：

1. **创建数据层**
   ```
   src/
   ├── data/
   │   ├── keywords.json       # 关键词数据（1000个）
   │   ├── tools.json          # 工具配置
   │   └── content.json        # 内容数据
   ```

2. **创建布局**
   ```
   src/
   ├── layouts/
   │   ├── base.njk            # 基础布局
   │   ├── tool.njk            # 工具布局
   │   ├── landing.njk         # 落地页布局
   │   └── category.njk        # 分类布局
   ```

3. **创建模板**
   ```
   src/
   ├── tools.njk               # 工具列表页
   ├── landing.njk             # 落地页模板
   └── categories.njk          # 分类页面
   ```

4. **使用 Pagination 批量生成**
   ```yaml
   # src/tools.njk
   ---
   pagination:
     data: keywords
     size: 1
     alias: keyword
   permalink: "/tools/{{ keyword.slug }}/"
   ---
   
   <h1>{{ keyword.title }}</h1>
   <p>{{ keyword.description }}</p>
   ```

**预期工作量**：3-5天

### Phase 3：配置构建和部署（1天）

**目标**：配置构建和部署流程

**具体步骤**：

1. **配置构建脚本**
   ```json
   {
     "scripts": {
       "build": "eleventy",
       "dev": "eleventy --serve",
       "deploy": "wrangler pages deploy _site"
     }
   }
   ```

2. **配置 Cloudflare Pages**
   ```bash
   wrangler pages project create my-seo-site
   wrangler pages deploy _site
   ```

**预期工作量**：1天

### Phase 4：验证和测试（2-3天）

**目标**：验证所有功能正常工作

**具体步骤**：

1. **生成测试页面**
   ```bash
   npm run build
   ```

2. **本地预览**
   ```bash
   npm run dev
   ```

3. **验证 SEO 标签**
   - 检查 Schema.org、OG、Twitter Card
   - 检查 sitemap.xml、robots.txt

4. **部署到 Cloudflare Pages**
   ```bash
   npm run deploy
   ```

**预期工作量**：2-3天

### Phase 5：部署到 Cloudflare Pages（1天）

**目标**：部署到 Cloudflare Pages，开始接收流量

**具体步骤**：

1. **部署到 Cloudflare Pages**
   ```bash
   npm run build
   wrangler pages deploy _site
   ```

2. **提交到搜索引擎**
   - Google Search Console：提交 sitemap.xml
   - Bing Webmaster Tools：提交 sitemap.xml
   - AI 搜索引擎：提交 llms.txt

**预期工作量**：1天

## 结论

### 决策理由

1. **不重复造轮子**：11ty 已经完美解决了程序化生成的所有问题
2. **官方完全支持**：Cloudflare Pages 官方完全支持
3. **成熟稳定**：10+ 年历史，生产环境验证
4. **JavaScript 生态**：与我们的技术栈匹配
5. **部署流程相同**：`npm run build` → `wrangler pages deploy`
6. **社区支持**：大型社区，遇到问题有社区帮助

### 保留的组件

- cf-core（Workers 共享内核）
- cf-shop/cf-api/cf-tools/cf-form（Workers 模板）
- 部署脚本（one-click.sh）
- 所有基础设施工作

### 改变的组件

- cf-static 从自定义脚本迁移到 11ty
- 部署流程不变

### 预期收益

- **节省开发时间**：3-4周
- **降低维护成本**：显著降低
- **提升质量**：功能完整性、稳定性、社区支持显著提升
