> 日期：2026-05-30  
> 铁律编号：#120  
> 严重程度：P0（每次部署必查）

---

## 核心问题

Cloudflare 有两种凭证，**权限面完全不同**，混用会导致部署失败：

| 凭证类型 | 前缀 | 认证方式 | 典型权限 | 适用场景 |
|---------|------|---------|---------|---------|
| **API Token** | `cfat_...` | `Authorization: Bearer` | Account: Pages/Workers<br>⚠️ **通常无 Zone DNS** | Pages/Workers 部署、GitHub Actions |
| **Global API Key** | `cfk_...` | `X-Auth-Email` + `X-Auth-Key` | **全部权限**，包括 Zone DNS Read/Edit | DNS 记录管理、域名绑定 |

---

## 为什么需要两种凭证

### API Token 的权限限制

API Token 是**受限凭证**，创建时选择权限范围。常见的 Token 只有：

```
Account → Cloudflare Pages → Edit
Account → Cloudflare Workers → Edit
```

**没有**以下权限：

```
Zone → DNS → Read
Zone → DNS → Edit
```

因此用 API Token 调用 DNS API 会返回：

```
HTTP 403 Authentication error
```

### Global API Key 的完整权限

Global API Key 是**主凭证**，拥有账户的全部权限，包括：

```
Zone → DNS → Read/Edit
Zone → Zone → Read
Account → 全部
```

但 Global API Key **不能**用 `Authorization: Bearer` 认证，必须用：

```
X-Auth-Email: your-email@example.com
X-Auth-Key: cfk_...
```

## 环境变量配置

### 必需（Pages/Workers 部署）

```bash
export CLOUDFLARE_API_TOKEN="cfat_..."
```

### 推荐（域名绑定需要）

```bash
export CF_AUTH_EMAIL="mailforwdy@gmail.com"
export CF_GLOBAL_API_KEY="cfk_..."
```

### 完整配置（一次性设置，后续无需重复）

```bash
# 部署用
export CLOUDFLARE_API_TOKEN="cfat_ue16s4yVUHOfR8iwkrSfY7oJNU2QPggwyQVMO6DE6e5258c6"

# DNS 用（域名绑定）
export CF_AUTH_EMAIL="mailforwdy@gmail.com"
export CF_GLOBAL_API_KEY="cfk_你的GlobalAPIKey"

# Turso 数据库（非 pages 模式需要）
export TURSO_API_TOKEN="turso_..."
```

## 部署脚本的凭证使用

### shared.sh 的自动选择逻辑

`shared.sh` 提供两个 API 函数：

| 函数 | 用途 | 认证方式 |
|------|------|---------|
| `cf_api()` | Pages/Workers API | 只用 `CLOUDFLARE_API_TOKEN` |
| `cf_dns_api()` | Zone DNS API | 优先 `CF_AUTH_EMAIL + CF_GLOBAL_API_KEY`，回退到 `CLOUDFLARE_API_TOKEN` |

`cf_dns_api()` 的选择逻辑：

```bash
if [ -n "${CF_AUTH_EMAIL:-}" ] && [ -n "${CF_GLOBAL_API_KEY:-}" ]; then
  # 使用 Global API Key（DNS 一定有权限）✅
  curl -H "X-Auth-Email: ${CF_AUTH_EMAIL}" -H "X-Auth-Key: ${CF_GLOBAL_API_KEY}" ...
elif [ -n "${CLOUDFLARE_API_TOKEN:-}" ]; then
  # 回退到 API Token（可能 403）⚠️
  curl -H "Authorization: Bearer ${CLOUDFLARE_API_TOKEN}" ...
else
  log_error "DNS API 缺少凭证"
  return 1
fi
```

### 00-init-project.sh 的预检

部署脚本在 Step 2 会检查 DNS 凭证：

```
[OK]    CLOUDFLARE_API_TOKEN 已设置 (53 字符)
[WARN]  未设置 DNS 凭证 (CF_AUTH_EMAIL / CF_GLOBAL_API_KEY)
[WARN]  如果后续需要绑定域名，请提供 Global API Key
```

**警告不阻塞部署**，但如果没有 DNS 凭证，Step 04（域名绑定）会失败。

### 04-bind-domain.sh 的验证

域名绑定脚本在 Step 3 会验证 DNS 权限：

```bash
if cf_check_dns_auth "$ZONE_ID"; then
  log_ok "DNS 权限验证通过"
else
  log_error "DNS 权限验证失败！"
  log_error "请提供 Global API Key"
  exit 1
fi
```

## 实际案例：opc.eforge.xyz 部署失败

### 问题

部署 `freelancer-calc` 到 `opc.eforge.xyz` 时，Step 04 失败：

```
[ERROR] Cloudflare DNS API POST /zones/.../dns_records: Authentication error
```

### 根因

1. 只提供了 `CLOUDFLARE_API_TOKEN` (cfat_...)
2. 该 Token 只有 Pages 权限，无 Zone DNS 权限
3. 脚本用 Bearer Token 调用 DNS API，返回 403

### 修复

提供 Global API Key 后重新运行：

```bash
cd /Users/dingyuwang/0-X/freelancer-calc

CLOUDFLARE_API_TOKEN="cfat_..." \
CF_AUTH_EMAIL="mailforwdy@gmail.com" \
CF_GLOBAL_API_KEY="cfk_..." \
DOMAIN="opc.eforge.xyz" \
ONLY=04 bash .deploy/one-click.sh
```

### 结果

```
[OK]    DNS 权限验证通过（使用 Global API Key）
[OK]    DNS CNAME 记录创建成功: abc123...
[OK]    Pages 域名绑定完成: opc.eforge.xyz → freelancer-calc
[OK]    HTTPS 已就绪 (HTTP 200, 第 3 次检查)
✅ 域名绑定完成
```

## 获取 Global API Key

1. 打开 https://dash.cloudflare.com/profile/api-tokens
2. 找到 **Global API Key** 区域（不是 API Token 列表！）
3. 点击 **View** → 输入密码 → 复制 `cfk_...` 值

⚠️ **Global API Key 是账户主凭证，权限极高，不要提交到 Git 或日志中。**

---

## 铁律

**铁律 #120：Cloudflare 凭证分层使用**

1. API Token (cfat_...) 只用于 Pages/Workers 部署
2. Zone DNS 操作必须用 Global API Key (cfk_...)
3. 部署脚本必须同时接受两种凭证，自动选择
4. 缺少 DNS 凭证时给出明确警告，不阻塞部署
5. DNS API 调用失败时提示 Global API Key 获取位置
