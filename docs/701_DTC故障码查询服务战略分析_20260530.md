# DTC 故障码查询服务战略分析 — 站在行业高度的创业路线图

> 日期：2026-05-30
> 定位：个人开发者创业，CF Free + Turso Free + GitHub 技术栈
> 数据资产：18,805 条汽车 DTC + ~500+ 条品牌工业故障码 + 统一清洗流水线
> 核心问题：DTC 码查询服务是否有价值？如何有效开展？

---

## 一、核心结论

| 维度 | 评估 |
|------|------|
| **DTC 查询服务本身的价值** | ⚠️ **中等** — 数据本身是公开的，单纯"查询"竞争激烈 |
| **我们的差异化优势** | ✅ **极高** — 汽车+工业跨领域数据库 + 数据清洗管道 = 别人复制不了 |
| **推荐策略** | **不做"查 DTC"，做"故障码知识平台"** — OBD 码 + 工业码 + 维修方案一体化 |
| **变现路径** | API 收费 + 网站广告 + 高级分析报告 |
| **最大机会** | GEO：AI 搜索时代，结构化故障码数据天然被 AI 引用 |

### 2.2 市场格局：我们不是第一个，但可以是最特别的一个

| 类型 | 代表玩家 | 覆盖 | 优势 | 弱点 |

| **我们（目标）** | — | 汽车+工业+跨行业 | 结构化数据、API、GEO优化 | 新建站域名权重低 |

### 2.3 2026 年的关键变数：AI 搜索正在重塑流量格局

传统 DTC 站依赖 Google SEO 获取"P0420"搜索流量。但：

```
搜索场景变化（2024 → 2026）

用户过去：在 Google 搜 "P0420" → 点击 obd-codes.com → 看广告
           ↓
用户现在：在 ChatGPT 问 "Check engine light P0420" 
          → AI 直接回答 "催化剂效率低"
          → 不点击任何网站
          ↑
          ⚠️ 传统 DTC 站流量在消失
```

**但这对我们是好事。**

原因是：
- 传统大站靠域名权重拿到 Google 前 10，但 AI 搜索会引用排名 20 以后的优质内容
- **89% 的 ChatGPT 引用来源是 Google 排名 20 名以后的内容**（700 文档数据）
- 我们的页面如果结构化数据做得好（Schema.org），AI 更容易引用
- 而且我们可以在 API 文档里写"由 AI 引用" → 收割 AI 搜索流量

## 三、我们的真实护城河：不是 DTC 数据，是数据清洗管道

### 3.1 伪命题澄清

**"我们有 18,805 条 DTC" ❌ 这不是护城河**

DTC 数据来自开源项目 `Wal33D/dtc-database`（MIT License），任何人都可以下载。单纯做"DTC 查询"没有壁垒。

### 3.2 真正的护城河

```
┌──────────────────────────────────────────────────────────────────────┐
│                   真正的护城河                                          │
│                                                                        │
│  1. 清洗管道 —— 从 PDF/HTML/手册中自动提取故障码的流水线               │
│     ├── 目录智能定位（TOCParser）                                      │
│     ├── 故障章节定位器（FaultChapterLocator）                          │
│     ├── 多格式解析（PDF/DOCX/XLSX/TXT）                               │
│     ├── LLM 增强提取                                                   │
│     └── 质量评分器（QualityScorer）                                    │
│                                                                        │
│  2. 结构化能力 —— 将非结构化数据变成结构化字段                         │
│     ├── FaultCode 模型（code, domain, description, cause, remedy）     │
│     ├── 统一归一化器（FaultCodeNormalizer）                            │
│     └── 跨行业适配（INDUSTRIAL/AUTOMOTIVE/ecom/psy）                   │
│                                                                        │
│  3. 农业化能力 —— 用 AI 自动持续收割数据                              │
│     ├── 自主探索器（Explorer）                                         │
│     ├── 策略进化（Strategy Evolution）                                 │
│     ├── 增量 Checkpoint                                                │
│     └── 经验存储（Experience Store）                                   │
│                                                                        │
│  综合结论：别人拿到 DTC 原始数据也没用，                               │
│  但我们可以持续产出 结构化+高可信度+跨领域 的故障码数据。             │
└──────────────────────────────────────────────────────────────────────┘
```

## 四、产品路线图（三阶段）

**目标**：用最小成本上线一个可用的 DTC 查询站，验证 SEO 和 API 模式

**使用现有模板**：
- 静态页面 → **cf-static 模板**（生成 SEO 页面）
- API → **cf-api 模板**（DTC 查询 API）
- 数据库 → **cf-core 的 db 模块**（Drizzle ORM 连接 Turso）

**SEO 页面数量**：18,805 页（每页 1 个 DTC 码）+ 34 品牌页 + 4 系统页 ≈ **19,000 页**

### Phase 2（第 3-6 周）：增值数据 + API 变现

**在 MVP 基础上增加**：

| 特性 | 技术实现 | 商业模式 |
|------|---------|---------|
| **中文描述** | 用 LLM 为 9,415 条通用码翻译中文描述 | 覆盖中文搜索流量 |
| **维修方案** | 从维修手册提取 + LLM 生成维修步骤 | 差异化内容，提高引用率 |
| **零件关联** | DTC → 可能故障零件 → 购买链接 | 联盟佣金 |
| **多码分析** | 输入多个 DTC，输出综合诊断报告 | 高级 API 功能 |
| **API Keys** | 用 cf-core 的 auth 模块管理 | API 按量计费 |

**API 定价方案**：
```
免费: 50 次/天（无 Key）
开发者: $9/月（5,000 次）
专业: $49/月（50,000 次）
企业: $199/月（无限 + 多码分析）
```

**预计收入（Phase 2 末期）**：
- API 订阅：5-10 个付费用户 ≈ $50-500/月
- 广告收入：流量 1,000-5,000/月 ≈ $10-50/月
- 联盟佣金：低

## 八、更广阔的图景：故障码知识平台的终极形态

### 8.1 如果只做 DTC 查询

```
→ 一个 DTC 查询站
→ 月收入 $200-1000
→ 可以，但天花板低
```

### 8.2 如果我们做"故障码知识平台"

```
→ DTC + 工业码 + 家电码 + 医疗报警码
→ 全球最大的结构化故障码数据库
→ API 生态（嵌入各种诊断工具）
→ AI training data（模型训练需要结构化故障码数据）
→ 月收入 $5,000-50,000+
→ 有真正的护城河
```

### 8.3 为什么工业故障码是战略资产

我们不能停留在 DTC，因为：

```
DTC 的局限：
- 数据量固定（18,805 条，不可能无限增长）
- 数据格式简单（只有 code + description）
- 竞争门槛低（人人可下载）

工业故障码的优势：
- 数据量可以持续增长（百万级，从 PDF/手册中提取）
- 数据格式丰富（描述 + 原因 + 维修措施 + 品牌特定）
- 竞争门槛高（需要工业领域知识 + PDF 提取能力）
- 与 DTC 同平台→交叉导流→飞轮效应
```

这正是我们已有 **autoclean 清洗管道** 的用武之地。

## 九、最终建议

### 做，但是要聪明地做

| 建议 | 理由 |
|------|------|
| **✅ 马上做 Phase 1（DTC 查询站）** | 3-5 天上线，零成本，验证假设 |

| **✅ 把 API 作为核心变现** | 广告收入不可靠，API 可预测 |
| **✅ 全力做 GEO** | AI 搜索是小站的翻身机会 |
| **⚠️ 不要试图和 obd-codes 抢 SEO** | 域名权重至少差 10 年，做 GEO 绕过 |
| **✅ 利用数据清洗管道持续扩张数据** | 这是我们的真实护城河 |
| **❌ 不要自己写完整 DTC 数据库** | 已经有 MIT 开源的，直接复用 |
