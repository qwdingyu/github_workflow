当前 Cloudflare token 已实测可用：

```text

```

```text
X-Auth-Email: mailforwdy@gmail.com
X-Auth-Key: cfk_...
```

实测结果：

```text
GET /user -> success
GET /zones/<zone_id>/dns_records -> success
```

结论：

```text
cfk_... 是可用的 Cloudflare Global API Key，但不能作为 Bearer token 使用。
```

## 为什么 ai.eforge.xyz 能成功

`ai.eforge.xyz` 是 Worker 项目，成功路径是：

```text
Worker
-> Workers Custom Domains API
-> ai.eforge.xyz
```

核心接口：

```text
PUT /accounts/{account_id}/workers/domains
```

该接口使用 Account 级 Workers Custom Domain 能力，传入：

```json
{
  "environment": "production",
  "hostname": "ai.eforge.xyz",
  "service": "gptsession2cpaandsub2api",
  "zone_id": "<zone_id>"
}
```

当时并没有使用：

```text
zones/{zone_id}/dns_records
```

所以不能据此判断当前 token 拥有普通 DNS records 权限。

## 为什么 shop.eforge.xyz 不同

`shop.eforge.xyz` 是 Cloudflare Pages 项目，路径是：

```text
Pages project
-> Pages custom domain
-> DNS CNAME
-> HTTPS certificate
```

Pages custom domain API 只能把域名加到 Pages 项目中。DNS 仍然必须存在：

```text
shop.eforge.xyz CNAME vibox-shop.pages.dev
```

当前 Pages 绑定已创建，但 Cloudflare 返回：

```text
CNAME record not set
```

这不是部署失败，而是 DNS CNAME 缺失。

## 当前保留脚本

### 1. Pages GitHub + Domain + DNS 脚本

路径：

```text
scripts/cloudflare/pages_github_domain_workflow.mjs
```

用途：

- 确认或创建 GitHub 集成型 Cloudflare Pages 项目。
- 确认或创建 Pages custom domain。
- 确认或创建 DNS CNAME。

命令：

最小配置：

```bash
CF_AUTH_EMAIL="<cloudflare-login-email>" \
CF_GLOBAL_API_KEY="<global-api-key>" \
CF_CUSTOM_DOMAIN="tool.eforge.xyz" \
node ../scripts/cloudflare/pages_github_domain_workflow.mjs
```

可选稳定性配置：

```bash
CF_REQUEST_RETRIES=3
CF_REQUEST_RETRY_DELAY_MS=1000
```

这两个值默认已经启用。只有 Cloudflare API 网络不稳定、`429` 或 `5xx` 较多时才需要调整。

保留覆盖配置：

```bash
CF_API_TOKEN="<token>" \
CF_DNS_AUTH_EMAIL="<cloudflare-login-email>" \
CF_DNS_GLOBAL_API_KEY="<global-api-key>" \
CF_ACCOUNT_ID="<account_id>" \
CF_ZONE_ID="<zone_id>" \
CF_PAGES_PROJECT="vibox-shop" \
CF_GITHUB_OWNER="qwdingyu" \
CF_GITHUB_REPO="vibox-shop" \
CF_CUSTOM_DOMAIN="shop.eforge.xyz" \
node scripts/cloudflare/pages_github_domain_workflow.mjs
```

最终实测结果：

```text
Pages project exists: vibox-shop
Pages custom domain exists: shop.eforge.xyz (active)
DNS CNAME already correct: shop.eforge.xyz -> vibox-shop.pages.dev
```

结论：

```text
脚本正确；Pages 用 Bearer token，DNS 用 Global API Key，完整链路可执行。
```

二次实测 `xtools`：

```text
Project: xtools
GitHub: qwdingyu/xtools
Custom domain: tool.eforge.xyz
Cloudflare returned subdomain: xtools-7nq.pages.dev
DNS CNAME: tool.eforge.xyz -> xtools-7nq.pages.dev
Domain status: active
HTTPS: HTTP/2 200
```

关键修正：

```text
不能自行拼接 <project>.pages.dev；必须读取 Pages project.subdomain。
```

二次幂等复跑时曾出现：

```text
Pages project exists: xtools
Pages custom domain exists: tool.eforge.xyz (active)
DNS CNAME already correct: tool.eforge.xyz -> xtools-7nq.pages.dev
socket hang up
```

判断：

```text
这不是配置错误，而是 Cloudflare API 请求过程中的瞬时连接中断。
```

处理：

```text
pages_github_domain_workflow.mjs 已内置请求重试。
默认 CF_REQUEST_RETRIES=3，CF_REQUEST_RETRY_DELAY_MS=1000。
```

### 2. Workers Custom Domain 脚本

路径：

```text
scripts/cloudflare/workers_custom_domain_bind.mjs
```

用途：

- 复用 `ai.eforge.xyz` 的成功模式。
- 查询 Workers Custom Domains。
- 绑定 Worker 到正式子域名。
- 从已有 custom domain 推导 Worker service。
- 支持新增域名后再显式确认删除旧域名。

命令：

最小新增域名模式：

```bash
CF_AUTH_EMAIL="<cloudflare-email>" \
CF_GLOBAL_API_KEY="<global-api-key>" \
CF_SOURCE_CUSTOM_DOMAIN="ai.eforge.xyz" \
CF_CUSTOM_DOMAIN="auth.eforge.xyz" \
node scripts/cloudflare/workers_custom_domain_bind.mjs
```

完整覆盖模式：

```bash
CF_API_TOKEN="<token>" \
CF_ACCOUNT_ID="<account_id>" \
CF_ZONE_ID="<zone_id>" \
CF_WORKER_SERVICE="gptsession2cpaandsub2api" \
CF_CUSTOM_DOMAIN="ai.eforge.xyz" \
node scripts/cloudflare/workers_custom_domain_bind.mjs
```

删除旧域名必须显式确认：

```bash
CF_AUTH_EMAIL="<cloudflare-email>" \
CF_GLOBAL_API_KEY="<global-api-key>" \
CF_SOURCE_CUSTOM_DOMAIN="ai.eforge.xyz" \
CF_CUSTOM_DOMAIN="auth.eforge.xyz" \
CF_DELETE_SOURCE_CUSTOM_DOMAIN=true \
CF_REPLACE_CONFIRM="ai.eforge.xyz->auth.eforge.xyz" \
node scripts/cloudflare/workers_custom_domain_bind.mjs
```

详细说明：

```text

```

当前实测：

```text

-> success
ai.eforge.xyz -> gptsession2cpaandsub2api
```

结论：

```text
Workers Custom Domains 自动化路径可用。
```

### 3. Cloudflare 权限探针脚本

路径：

```text
scripts/cloudflare/capability_probe.mjs
```

用途：

- 一键检查 token 是否能验证。
- 检查 Pages 项目权限。
- 检查 Workers Custom Domains 权限。
- 检查 Zone DNS records 权限。

命令：

```bash
CF_AUTH_EMAIL="<cloudflare-login-email>" \
CF_GLOBAL_API_KEY="<global-api-key>" \
CF_ACCOUNT_ID="<account_id>" \
CF_ZONE_ID="<zone_id>" \
CF_PAGES_PROJECT="vibox-shop" \
node scripts/cloudflare/capability_probe.mjs
```

期望输出示例：

```text
OK Pages projects list HTTP 200
OK Pages deployments list HTTP 200
OK Workers custom domains list HTTP 200
OK Zone DNS records list HTTP 200
```

如果使用只包含 Pages/Workers 权限的 Bearer token，最后一行可能失败；如果使用当前 Global API Key 模式，应全部 OK。

## 标准判断表

| 项目类型 | 推荐平台 | 域名 API | 是否需要 DNS records 权限 |
| --- | --- | --- | --- |
| Worker 应用 | Cloudflare Workers | Workers Custom Domains | 通常不需要直接操作 DNS records |
| 静态落地页 | Cloudflare Pages | Pages Custom Domain + DNS CNAME | 需要 |
| 静态资源 + 简单函数 | Cloudflare Pages Functions | Pages Custom Domain + DNS CNAME | 需要 |
| 传统 VPS 服务 | VPS + Cloudflare DNS | DNS A/CNAME | 需要 |

## Cloudflare Pages 可用命令

查询项目：

```bash
curl -sS "https://api.cloudflare.com/client/v4/accounts/<account_id>/pages/projects/<project>" \
  -H "Authorization: Bearer <token>"
```

查询部署：

```bash
curl -sS "https://api.cloudflare.com/client/v4/accounts/<account_id>/pages/projects/<project>/deployments" \
  -H "Authorization: Bearer <token>"
```

查询域名：

```bash
curl -sS "https://api.cloudflare.com/client/v4/accounts/<account_id>/pages/projects/<project>/domains" \
  -H "Authorization: Bearer <token>"
```

## Cloudflare Workers 可用命令

查询 Workers Custom Domains：

```bash
curl -sS "https://api.cloudflare.com/client/v4/accounts/<account_id>/workers/domains" \
  -H "Authorization: Bearer <token>"
```

绑定 Workers Custom Domain：

```bash
curl -sS -X PUT "https://api.cloudflare.com/client/v4/accounts/<account_id>/workers/domains" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  --data '{"environment":"production","hostname":"ai.eforge.xyz","service":"gptsession2cpaandsub2api","zone_id":"<zone_id>"}'
```

## 当前需要补齐的权限

为了让 `shop.eforge.xyz` 和后续 Pages 项目也能全自动完成，需要创建或更新一个 Domain DNS Token：

```text
Zone -> DNS -> Read
Zone -> DNS -> Edit
Zone resource -> eforge.xyz
```

有了这个权限后，脚本会自动创建：

```text
shop CNAME vibox-shop.pages.dev
```

本次已经用 Global API Key 完成：

```text
shop.eforge.xyz CNAME vibox-shop.pages.dev
proxied=false
```

并验证：

```text

Pages custom domain status -> active
```
