# AcctBox V2 实施记录与踩坑

## 背景

`acctbox` 按 V2 蓝图开始实施。第一阶段目标不是做大后台，而是把 V1 已验证的发卡链路升级为轻量可维护底座：

```text
TypeScript + Hono + Zod
Drizzle ORM 普通查询
Wrangler D1 migrations
兑换码发卡
订单 token 查询
ADMIN_TOKEN 管理端
卡密导入
manual 确认发卡
永久 smoke 脚本
```

## 业务调整

由于当前没有支付功能，先用“兑换码”代替支付确认：

```text
1. 用户下单必须输入兑换码。
2. 兑换码无效时不创建订单、不扣库存。
3. direct 商品兑换成功后直接展示卡密。
4. manual 商品兑换成功后进入 pending，由管理员确认后发卡。
5. 未配置邮件时，页面和 lookup 接口就是主交付方式。
```

## Drizzle ORM 边界

执行规则：

```text
能用 ORM 的普通 CRUD，优先使用 drizzle-orm。
涉及 D1 原子发卡的 UPDATE ... RETURNING 保留参数化 raw SQL。
```

原因：

```text
发卡库存领取必须单语句完成，避免先查再改造成重复发卡。
raw SQL 只允许 prepare().bind()，禁止拼接用户输入。
```

## 踩坑：orders.status CHECK 约束

### 背景

V1 `orders.status` 只允许：

```text
issued / sold_out / failed
```

V2 manual 模式需要：

```text
pending / paid / issued / expired / canceled / failed
```

### 现象

管理端 smoke 在创建 manual 订单时返回 HTTP 500。

### 原因

SQLite/D1 无法直接修改已有 CHECK 约束。`0002_v2_core.sql` 虽然添加了字段，但旧 CHECK 仍然存在，插入 `pending` 失败。

### 解决方案

新增正式迁移：

```text
acctbox/migrations/0003_rebuild_orders_status.sql
```

采用“备份子表 -> 重建 orders -> 恢复子表”的方式，避免外键引用导致：

```text
FOREIGN KEY constraint failed
```

### 建议

```text
1. 状态机字段的 CHECK 要谨慎。
2. 线上表改 CHECK，不要写临时 SQL，要写 migration。
3. 被外键引用的表重建时，必须处理子表。
4. 这类脚本必须保留，不能调完就删。
```
