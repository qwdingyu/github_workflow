# AcctBox V2 实施记录与踩坑

## 背景

`acctbox` 按 V2 蓝图开始实施。第一阶段目标不是做大后台，而是把 V1 已验证的发卡链路升级为轻量可维护底座：

```text
TypeScript + Hono + Zod
Drizzle ORM 普通查询
Wrangler D1 migrations
兑换码发卡
订单 token 查询
ADMIN_TOKEN 管理端
卡密导入
manual 确认发卡
永久 smoke 脚本
```

## 业务调整

由于当前没有支付功能，先用“兑换码”代替支付确认：

```text
1. 用户下单必须输入兑换码。
2. 兑换码无效时不创建订单、不扣库存。
3. direct 商品兑换成功后直接展示卡密。
4. manual 商品兑换成功后进入 pending，由管理员确认后发卡。
5. 未配置邮件时，页面和 lookup 接口就是主交付方式。
```

## 产品判断：兑换码是否多余

如果只是一次性交付卡密，兑换码流程确实比管理员直接发卡密多一步。

但 AcctBox 的目标是验证 Web 端完整闭环：

```text
宣传页
商品展示
兑换领取
订单留痕
lookup 补偿查询
管理端维护
后续传播和复购入口
```

因此推荐保留兑换码，但必须做到：

```text
1. 管理端按商品生成兑换码。
2. 用户兑换成功后直接展示卡密。
3. 用户网络中断时可以通过 order_token lookup 查询。
4. 管理员可以在后台查订单和卡密，必要时人工补发。
```

如果项目完全不需要 Web 宣传和查单，才退化为“管理员直接发卡密”。

## UI 调整：用户端和管理端分离

用户反馈截图显示第一版 UI 存在明显问题：

```text
1. 用户需要填联系方式、邮箱、兑换码、活动码、邀请码，流程过重。
2. 普通用户界面出现“管理”，不符合产品边界。
3. 页面文案有开发验证痕迹。
4. 浅色界面和卡片布局缺少数字权益产品的质感。
```

调整后：

```text
1. 用户端只保留兑换码。
2. 普通导航只保留兑换和查询。
3. /admin 独立进入管理端。
4. 查询支持订单 Token 或一次性兑换码。
5. 视觉改为黑色科技感主题。
```

结论：

```text
发卡产品的用户端必须极简。
复杂信息留给管理端，用户只做一件事：输入兑换码并领取。
```

## 追加踩坑：/admin 通过 challenge 后显示首页

### 现象

访问 `https://acctbox.eforge.xyz/admin` 通过 Cloudflare challenge 后，页面显示普通用户首页。

### 判断

这不是域名绑定错误。`curl -I` 显示：

```text
cf-mitigated: challenge
HTTP 403
```

说明 WAF 正在保护 `/admin`，配置层生效。

### 根因

根因是 Cloudflare Static Assets **默认的 `html_handling`** 行为：

```text
assets.html_handling = "auto-trailing-slash"  (默认值)
```

对于 `/admin` 这种无扩展名路径，Cloudflare 自动做 trailing-slash 检查：找不到 `admin.html` 也没有 `admin/index.html`，就 307 到 `/`——**这个过程在 Worker 执行之前就发生了**。

`run_worker_first: true` 不影响此行为，因为 Static Assets 的 HTML 规范化是路由层逻辑，先于 Worker 分流。

此外前端最初也只识别精确 `/admin`，没有覆盖 `/admin/`。

### 修复方案

首次修复（不正确）：
- `run_worker_first: true` → 无效，问题根源不在 Worker 分流

最终正确修复（三管齐下）：

```text
1. html_handling: "none"                        # 禁止静态层做自动 URL 规范化重定向
2. not_found_handling: "single-page-application" # 非资产路径回退到 index.html
3. run_worker_first: ["/admin", "/admin/*", "/lookup", "/order", "/api/*"]
```

| 配置项 | 作用 |
|---|---|
| `html_handling: "none"` | 🔑 **关闭自动 307**，/admin 不再被规范化到 / |
| `not_found_handling: "single-page-application"` | /admin 404 → 返回 /index.html |
| `run_worker_first` | Worker 先执行，做精细路由（API / 后台 / 静态） |

### 误判点

最初以为只靠 `run_worker_first: true` 就能解决。实际 deploy 后：

```bash
curl -sI https://acctbox.mailforwdy.workers.dev/admin
# HTTP/2 307 → /      ← 仍跳转！证明非 run_worker_first 问题
```

说明 `html_handling` 的自动规范化行为**独立于 Worker 路由层**，必须在 assets 配置中显式关闭。

### 为什么这是当前最佳实践

AcctBox 不是纯静态站，而是带后台、D1、兑换码、lookup 的轻量 Worker 应用。对这类项目，路由确定性比少一次 Worker 调用更重要。

局部配置：

```text
run_worker_first: ["/api/*", "/admin", "/admin/*"]
```

在实际部署中仍出现过 `/admin -> 307 -> /`。为了避免下一次项目继续踩同一个坑，带后台/lookup/API 的 Cloudflare Worker + Assets 项目统一采用：

```text
assets.run_worker_first=true
```

然后在 Worker 中显式分流：

```text
/api/* -> Hono API
/admin、/admin/*、/lookup、/order -> /index.html
其他路径 -> ASSETS
```

### 建议

```text
WAF challenge 继续保留。
不要为了解决前端路由问题放松 /admin 防护规则。
不要再用“/admin 返回了 challenge”作为后台可用的完成证据。
```

## Drizzle ORM 边界

执行规则：

```text
能用 ORM 的普通 CRUD，优先使用 drizzle-orm。
涉及 D1 原子发卡的 UPDATE ... RETURNING 保留参数化 raw SQL。
```

原因：

```text
发卡库存领取必须单语句完成，避免先查再改造成重复发卡。
raw SQL 只允许 prepare().bind()，禁止拼接用户输入。
```

## 踩坑：orders.status CHECK 约束

### 背景

V1 `orders.status` 只允许：

```text
issued / sold_out / failed
```

V2 manual 模式需要：

```text
pending / paid / issued / expired / canceled / failed
```

### 现象

管理端 smoke 在创建 manual 订单时返回 HTTP 500。

### 原因

SQLite/D1 无法直接修改已有 CHECK 约束。`0002_v2_core.sql` 虽然添加了字段，但旧 CHECK 仍然存在，插入 `pending` 失败。

### 解决方案

新增正式迁移：

```text
acctbox/migrations/0003_rebuild_orders_status.sql
```

采用“备份子表 -> 重建 orders -> 恢复子表”的方式，避免外键引用导致：

```text
FOREIGN KEY constraint failed
```

### 建议

```text
1. 状态机字段的 CHECK 要谨慎。
2. 线上表改 CHECK，不要写临时 SQL，要写 migration。
3. 被外键引用的表重建时，必须处理子表。
4. 这类脚本必须保留，不能调完就删。
```

## 追加踩坑：ADMIN_TOKEN 不能放 vars

### 背景

为了本地管理端 smoke 方便，曾短暂把开发默认值放入 `wrangler.jsonc` 的 `vars`。

### 现象

远程部署输出里直接出现：

```text
env.ADMIN_TOKEN ("dev-only-change-me")
```

### 原因

`vars` 是普通环境变量，不是 secret。它会进入部署配置，也可能覆盖同名 secret。

### 解决方案

```text
1. 从 wrangler.jsonc 删除 ADMIN_TOKEN。
2. 生产只使用 wrangler secret put ADMIN_TOKEN。
3. 本地需要管理端时，通过 shell 环境变量或未提交的 .dev.vars 临时传入。
```

本地验证管理端推荐命令：

```bash
ADMIN_TOKEN="dev-only-change-me" rtk npm run dev:admin
```

### 建议

```text
任何鉴权 token 都不能进入 wrangler.jsonc、docs、README、seed.sql。
部署日志中看到 token 或默认 token，要立即回滚配置并重新部署。
```

## 踩坑：Admin Token 持久化安全漏洞

### 背景

2026-05-25 安全审计发现 Admin 面板的 Token 管理存在严重安全漏洞：

- **Token 存在 sessionStorage**（`app.js` 第 185 行：`sessionStorage.setItem(storedTokenKey, ...)`）
- **自动回填到密码输入框**（第 278 行：`adminTokenInput.value = savedToken`）
- **永不过期**：只要标签页不关，任意重复访问都自动授权
- **无退出机制**：没有 logout button 清除 Token

### 问题代码（已修复）

```javascript
// 原 app.js 中的安全漏洞代码
const storedTokenKey = "acctbox_admin_token";

adminLogin.addEventListener("submit", async (event) => {
  event.preventDefault();
  sessionStorage.setItem(storedTokenKey, adminTokenInput.value); // ← Token 持久化
  ...
});

// 页面加载时从 sessionStorage 回填
const savedToken = sessionStorage.getItem(storedTokenKey);
if (savedToken) {
  adminTokenInput.value = savedToken;  // ← 密码明文暴露
  ...
}
```

### 根因

前端 Vanilla JS 实现中，采用 `sessionStorage` 保存 Token 是设计缺陷。虽然 `sessionStorage` 比 `localStorage` 略有改善（标签页关闭即清除），但：
1. 同浏览器同标签页刷新后 Token 仍然存在
2. Token 明文显示在密码输入框中
3. 无法主动退出

### 修复方案

**前端**：重构为 Vue 3 + Element Plus 单页应用（`public/admin.html`）

| 安全措施 | 实现方式 |
|---|---|
| Token 在内存中 | Vue `ref('')`，不落 sessionStorage/localStorage |
| 刷新需重新登录 | 页面加载时 `token.value` 为空，弹出登录对话框 |
| 30 分钟无操作自动退出 | `inactivityTimer` 定时器清除内存 Token |
| 退出按钮 | `handleLogout()` 清除 `token.value`，显示登录对话框 |
| CSS 全页面滚动 | 不设 table fixed height，避免参考项目中的表内滚动 bug |

**后端**（不变）：
- 继续使用 Bearer Token 鉴权
- 已有操作审计日志（`admin_audit_logs` 表）
- 已有 IP 哈希记录

### 架构变更

| 文件 | 变更 |
|---|---|
| `public/admin.html` | **新建** Vue 3 + Element Plus 单文件 SPA（CDN，无构建步骤） |
| `src/index.ts` | Worker 路由 `/admin` 指向 `admin.html` |
| `public/index.html` | 移除 admin 段（`admin-shell`、`admin-view` 等） |
| `public/app.js` | 移除所有 admin 代码（`adminHeaders`、`loadAdmin`、`showAdmin`、`sessionStorage` 操作） |

### 设计决定

1. **全页面滚动**：表格不设固定高度（`el-table` 不设 `height` 属性），整个页面作为滚动容器。这是从参考项目 `admin.html` 的踩坑经验中吸取的教训——表内滚动在移动端和不同屏幕尺寸下适配困难。
2. **暗色主题**：匹配 AcctBox 现有的 `#05070c` 暗色背景。
3. **CDN 加载**：Vue 3 + Element Plus 通过 unpkg CDN 加载，无构建步骤。`public/` 目录下直接放 SPA 文件，Worker Static Assets 绑定直接服务。
4. **Token 生命周期**：纯内存变量。页面关闭或刷新后 Token 消失，必须重新输入。

### 建议

1. **后续可升级为 JWT**：如果管理端需要更细粒度的权限控制，可以引入签名 Token + TTL，后端校验过期时间。
2. **前端可分离部署**：`public/admin.html` 可以整体迁移到 Vercel，Worker 只保留 `/api/*`。迁移时只需修改 Worker 路由和 CORS 配置。
3. **操作审计**：已经在 admin 路由中植入 `writeAdminAudit` 调用，每次管理操作都会记录到 `admin_audit_logs` 表。
