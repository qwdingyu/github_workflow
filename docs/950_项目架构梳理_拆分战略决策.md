## 第一部分：现有代码真实状态（基于源码事实）

### 1.1 templates/cf-static 工具清单

当前共 **10 个工具**，分为两类：

#### A 类：中国特有计算器（2 个）

| 工具 | Slug | 技术实现 | 中国特色程度 |
|------|------|---------|------------|
| 五险一金计算器 | `social-insurance-calculator` | NJK 模板 + 119 城市数据 JS（341 行） | **100% 中国特有** — 北京/上海/广州/深圳/杭州/成都的社保费率 |
| 个税计算器 | `income-tax-calculator` | NJK 模板 + 税率表 JS（225 行） | **100% 中国特有** — 中国 7 级超额累进税率、专项附加扣除 |

**代码特征：**
- 使用 `type: "calculator"` 标记，有独立的渲染路径（`{% include tool.slug ~ '.njk' %}`）
- 数据硬编码在 JS 文件中（城市费率、税率表）
- 界面完全是中文（"税前月薪"、"专项附加扣除"）
- SEO 关键词全是中文（"五险一金"、"个税计算"）
- 需要**每年更新**（税率、费率、基数上下限变化）

#### B 类：通用开发者工具（8 个）

| 工具 | Slug | 市场 |
|------|------|------|
| JSON 格式化 | `json-formatter` | 全球通用 |
| Base64 编解码 | `base64-decode` | 全球通用 |
| MD5 哈希 | `md5-generator` | 全球通用 |
| 正则测试器 | `regex-tester` | 全球通用 |
| URL 编解码 | `url-encode-decode` | 全球通用 |
| HTML 转义 | `html-escape` | 全球通用 |
| 时间戳转换 | `timestamp-converter` | 全球通用 |
| UUID 生成器 | `uuid-generator` | 全球通用 |

**代码特征：**
- 使用通用 form 模板（`textarea → 处理 → output`）
- 工具逻辑简单（单文件 < 50 行 JS）
- SEO 关键词目前是中文，但工具本身**天然可国际化**

### 1.3 Eleventy 架构事实

```
templates/cf-static/
├── .eleventy.js              ← 配置文件（45 行）
├── src/
│   ├── _data/
│   │   ├── config.json       ← 站点配置
│   │   ├── tools.json        ← 工具元数据（232 行，10 个工具）
│   │   ├── posts.json        ← 博客
│   │   └── docs.json         ← 文档
│   ├── _includes/
│   │   ├── income-tax-calculator.njk    ← 计算器 UI 模板
│   │   └── social-insurance-calculator.njk
│   ├── _layouts/
│   │   └── base.njk          ← 基础布局
│   ├── tools.njk             ← 工具页模板（pagination 驱动，168 行）
│   ├── tools-index.njk       ← 工具列表页
│   └── ...其他页面
├── assets/
│   ├── js/
│   │   ├── income-tax-calculator.js      ← 225 行
│   │   ├── social-insurance-calculator.js ← 341 行
│   │   ├── utils.js                      ← 共享工具函数
│   │   └── ...其他 8 个工具 JS（各 < 50 行）
│   └── styles.css
└── package.json              ← 依赖: @11ty/eleventy, wrangler, serve
```

**关键架构特点：**
- `tools.json` 是数据驱动的核心——加一个工具只需在数组里加一个对象
- 计算器有独立分支：`{% if tool.type == 'calculator' %}` → 用 include 模板
- 通用工具走统一 form 模板 → 各自 JS 实现 `processTool()`
- 每个工具自动生成独立页面：`/tools/{slug}/`
- 自带 FAQ 结构化数据（Schema.org）+ 内部链接

## 第二部分：eForge Monorepo 与 cf-static 的关系

### 2.1 Monorepo 架构事实

```
eForge Monorepo/
├── packages/cf-core/         ← 核心库（5 张基础设施表，TypeScript）
├── templates/
│   ├── cf-api/               ← API 模板（Cloudflare Workers + D1）
│   ├── cf-shop/              ← 电商模板（Workers + Vue 前端）
│   ├── cf-form/              ← 表单模板
│   ├── cf-tools/             ← 工具模板
│   ├── cf-static/            ← ★ 当前静态站（Eleventy）
│   └── cf-form/              ← 表单模板
├── dtc/                      ← 数字礼品卡项目（独立 Workers 项目）
└── eshop/                    ← 子模块（未检出）
```

### 2.2 关键矛盾：cf-static 与 Monorepo 铁律不兼容

| Monorepo 铁律 | cf-static 实际情况 | 兼容性 |
|--------------|-------------------|--------|
| 使用 pnpm | 使用 npm（`"preinstall": "npx only-allow pnpm"` 在根目录，但 cf-static 没有） | ⚠️ 不一致 |
| 基于 cf-core schema | 无数据库，纯静态 | ❌ 完全不适用 |
| Cloudflare Workers | Cloudflare Pages（静态） | ⚠️ 同生态但不同产品 |
| TypeScript | 纯 JS + Nunjucks | ⚠️ 不同技术栈 |

**结论：`cf-static` 实际上是 Monorepo 里的"异类"——它不需要 cf-core、不需要数据库、不需要 Workers。**
它只是恰好放在了这个仓库里，因为它也用 Cloudflare 生态部署。

## 第三部分：核心决策分析

### 决策 1：国内计算器是否拆分？

#### 方案 A：不拆分，留在 cf-static

| 维度 | 分析 |
|------|------|
| **优点** | |
| 维护简单 | 一个项目，一套部署流程 |
| 内部链接 | 计算器 ↔ 开发者工具互相导流 |
| 通用工具可复用 | 同一个 Eleventy 实例 |
| **缺点** | |
| SEO 混乱 | 中文站点混排，Google 不知道该给中文还是英文用户 |
| 更新频率冲突 | 中国税率每年变，开发者工具几乎不变 |
| 国际化障碍 | 整个站 `locale: zh-CN`，英文工具无法获得英文 SEO 权重 |
| 变现路径不同 | 计算器靠 AdSense/微信生态，开发者工具靠全球流量 |

#### 方案 B：拆分——计算器独立为 `cn-calculators` 项目

| 维度 | 分析 |
|------|------|
| **优点** | |
| SEO 清晰 | 中文站专注中文用户，英文站专注全球用户 |
| 独立域名 | 中文站可用 `.cn` 或中文品牌域名 |
| 更新解耦 | 税率更新不影响开发者工具 |
| 变现独立 | 中文站接微信/支付宝，英文站接 Stripe/AdSense |
| **缺点** | |
| 维护成本翻倍 | 两个 Eleventy 项目要分别维护 |
| 通用工具重复 | Base64、UUID 等如果中文站也需要，要复制 |
| 内部链接断裂 | 两个站之间的导流需要手动管理 |

#### 决策建议：**拆分，但用模板共享的方式**

```
理由：
1. 五险一金/个税是 100% 中国特有，永远不会面向国际市场
2. 8 个通用开发者工具是 100% 全球通用，应该面向国际市场
3. 两个市场的 SEO 策略、变现方式、用户群体完全不同
4. 用 Eleventy 模板共享，维护成本不翻倍
```

### 决策 2：国外项目如何启动？

#### 方案 A：在 cf-static 内加英文目录

```
templates/cf-static/src/
├── en/          ← 英文工具
├── zh/          ← 中文计算器
```

**❌ 不推荐。** 原因：
- Eleventy 的多语言支持需要 `@11ty/eleventy-plugin-i18n`，增加复杂度
- 同一个 `config.json` 无法同时服务两个 locale
- SEO 上，Google 对混合语言站点的排名低于纯语言站点
- `hreflang` 标签需要精确配对，容易出错

#### 方案 B：用脚手架创建全新项目

```bash
node scripts/create-project.mjs calculators --template cf-static
```

**⚠️ 半推荐。** 原因：
- `create-project.mjs` 是为 Workers 项目设计的（带 schema.ts），对纯静态站不完全适用
- 但 cf-static 本身就是一个模板，可以直接复制

#### 方案 C：复制 cf-static 为两个独立模板

```
templates/
├── cf-static/           ← 保留，专注全球开发者工具（英文）
├── cf-calculators/      ← 新建，专注中国计算器（中文）
```

**✅ 推荐。** 具体方案：

```
templates/
├── cf-static/                    ← 改造为国际站
│   ├── src/_data/config.json     ← locale: en-US
│   ├── src/_data/tools.json      ← 只保留 8 个通用工具 + 未来英文工具
│   └── ...                        ← 界面翻译为英文
│
├── cf-calculators/               ← 新建，复制 cf-static 结构
│   ├── src/_data/config.json     ← locale: zh-CN
│   ├── src/_data/tools.json      ← 只保留 2 个计算器
│   └── ...                        ← 保持中文
```

## 第五部分：关于脚手架的使用

### 5.1 现有脚手架能力

```javascript
// scripts/create-project.mjs 实际能力：
// - 基于模板复制目录
// - 修改 package.json name
// - 修改 wrangler.toml name
// - 生成 schema.ts（带 cf-core 公共表）
// - 生成 migration
```

### 5.2 脚手架的局限

```
❌ 不支持纯静态项目（总是生成 Workers + D1）
❌ 不支持 Eleventy 配置
❌ 不支持国际化
```

### 5.3 建议：增强脚手架

```javascript
// 在 create-project.mjs 中增加 --type static 选项：
// node scripts/create-project.mjs my-tools --template cf-static --type static
//
// 对于 static 类型：
// - 不生成 schema.ts
// - 不生成 wrangler.toml（改用 Pages 配置）
// - 复制 Eleventy 配置
// - 支持 --locale en-US / zh-CN 参数
```

## 第八部分：风险与注意事项

### 风险 1：Monorepo 铁律冲突

```
cf-static 和 cf-calculators 都是纯静态项目，
不使用 cf-core、不使用 D1、不使用 Workers。

这不违反铁律（铁律针对的是使用 cf-core 的项目），
但需要在 CLAUDE.md 中明确：
"cf-static 和 cf-calculators 是纯静态站模板，不受 cf-core 铁律约束。"
```

### 风险 2：pnpm vs npm

```
cf-static 当前没有 lock 文件约束。
建议：
- 根目录用 pnpm workspace 管理
- cf-static 和 cf-calculators 作为独立 npm 项目（因为它们只需要 eleventy）
- 或者统一改为 pnpm（推荐）
```

### 风险 3：内容重复

```
如果未来中文站也需要 Base64、UUID 等通用工具，
不要复制代码。方案：
- 创建一个 shared 目录放通用工具 JS
- 两个站通过 symlink 或 Eleventy 插件引用
```
