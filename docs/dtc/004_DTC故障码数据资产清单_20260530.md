## 五、注意事项

1. **dtc_unified.db 与 wal33d 的关系**：前者是后者的子集（12,128 vs 18,805），但有额外的 symptoms/causes/solutions 字段。通过 `code` 做 JOIN 可以补充约 2,000 条 cause。注意 `dtc_unified` 没有制造商维度，只按 code 去重。

2. **`completeness` 字段的含义**：0.3=仅描述（82.7%），0.5=部分填充（1%），0.7=有症状+原因（15.5%），0.85=较完整（0.45%），1.0=完整含解决方案（0.37%）—— 大多数记录的质量并不高。

3. **obd-codes 的局限性**：只覆盖了 2,229 个码，且集中在 Powertrain(P)，B(C)ody 只有 125 个，U 只有 2 个。

4. **工业故障码不是 DTC**：`fault_kb*.json` 中的数据是工业自动化领域的故障码（PLC/伺服/变频器），格式为 E001 / F01510 / CPF00 等，与汽车 OBD-II DTC 完全不同。未来统一时需要额外的归一化层。

5. **所有 `.db` 文件是 SQLite 格式**：可以直接用 `sqlite3 <file>` 命令读取，无需安装额外工具。
