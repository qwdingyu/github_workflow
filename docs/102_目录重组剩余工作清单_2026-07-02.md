## 二、P0 待办

### 1. 完成 `cf-calculators` 消费 npm 包闭环

**现状**

- `templates/cf-calculators/package.json` 未依赖 `@usethink/mach-calculators`。
- 公式逻辑仍在 `assets/js/*-calculator.js` 内以浏览器脚本形式维护。
- `tests/comprehensive-quote-verification.js` 仍以“浏览器端公式与 mach-formulas 一致”为目标。

**目标**

- 先选择一个低风险计算器做试点，例如 `comprehensive-quote-calculator`。
- 引入 `@usethink/mach-calculators` 的 npm 依赖。
- 明确浏览器端集成方式：
  - 方案 A：Eleventy 构建时从 npm 包生成浏览器可用 bundle。
  - 方案 B：将 npm 包作为公式真源，继续生成静态浏览器脚本，但禁止手工复制。
- 保留现有浏览器验证测试，新增“npm 包结果 = 浏览器结果”的回归测试。

**验收**

- `templates/cf-calculators` 构建通过。
- 至少一个计算器的公式来源切换到 `@usethink/mach-calculators`。
- 文档明确后续计算器迁移顺序。

### 2. 决策并落地 `freelancer-calc/` 归属

**现状**

- `freelancer-calc/` 位于根目录。
- 有 `package-lock.json`，不在 `pnpm-workspace.yaml`。
- 与根仓库“pnpm workspace 铁律”冲突。

**推荐**

- 如果它是线上独立产品：迁入 `products/freelancer-calc/` 或拆成独立仓库。
- 如果它要作为脚手架复用：迁入 `templates/cf-freelancer/` 并改造成模板。

**验收**

- 根目录不再直接放置 `freelancer-calc/`。
- `package-lock.json` 的存在原因被记录。
- 根文档和 workspace 配置同步。

### 3. 建立 `package-lock.json` 治理规则

**现状**

当前仓库发现：

```text
freelancer-calc/package-lock.json
templates/cf-shop/package-lock.json
```

**规则**

- 根 workspace 默认使用 pnpm，不允许新增 npm lockfile。
- 独立 npm 包或独立产品可以保留 `package-lock.json`，但必须满足：
  - 不作为根 pnpm workspace 成员，或有明确例外说明。
  - 在项目 README/docs 中说明为什么使用 npm。
  - CI 中使用 `npm ci`，不混用 pnpm install。

**验收**

- 新增一份 lockfile 例外清单。
- `freelancer-calc` 和 `templates/cf-shop` 分别给出处理结论。
