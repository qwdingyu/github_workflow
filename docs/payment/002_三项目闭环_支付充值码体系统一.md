# 三项目闭环改造：支付体系 & 充值码系统统一

> 日期：2026-05-30
> 目的：消除 `templates/cf-shop` 与 `eshop` / `cf-core` 之间的支付体系差异，实现统一的支付抽象层 + 充值码余额系统

---

## 背景

项目架构分为三层：

| 层 | 项目 | 职责 |
|---|------|------|
| 基础设施 | `packages/cf-core` | 共享内核（数据库、安全、支付抽象层） |
| 生产应用 | `eshop` | 线上发卡商城（完整功能，含 Stripe/TRC20/充值码） |
| 脚手架模板 | `templates/cf-shop` | 一键部署模板（create-project.mjs 的输出产物） |

**问题**：`templates/cf-shop` 是从 cf-core 诞生前创建的老模板，有三大不足：
1. `services/payments/` 下的 3 个文件是**死代码**（0 引用，接口与 cf-core 不兼容）
2. 只支持支付宝 + 手动确认，缺少余额支付、Stripe、USDT/TRC20
3. 没有充值码系统（无法快速变现）

## 核心架构变化

### 1. 支付方式矩阵

```
用户选择支付方式
    │
    ├── balance ──→ 查余额 → 扣减 → 创建订单 → 发卡 ← 无需等待
    │
    ├── alipay ──→ 创建订单 → 返回二维码 → 支付宝回调 → 验签 → 发卡
    │
    ├── stripe ──→ 创建订单 → 返回 URL → Stripe 回调 → HMAC 验签 → 发卡
    │
    ├── usdt_trc20 ──→ 创建订单 → 展示地址 → 轮询 TronGrid API → 发卡
    │
    └── manual ──→ 创建订单 → 待管理员后台上手动确认
```

### 2. 充值码业务闭环

```
管理员后台批量生成充值码（面值可自定义）
    │
    ▼
用户站外转账购买充值码（WeChat/Alipay/USDT）
    │
    ▼
用户在 /api/vouchers/redeem 输入码
    │  (Turnstile + 限流保护)
    ▼
原子条件 UPDATE → user_balances 余额增加
    │
    ▼
用户下单时选择「余额支付」
    │
    ▼
原子扣减 → 创建订单 → 自动发卡
```

### 3. 安全设计

| 场景 | 保护措施 |
|------|----------|
| 充值码枚举兑付 | 限流 5/min/IP + Turnstile + 条件 UPDATE |
| 余额透支 | SQL 表达式 `balanceCents >= amountCents` 原子检查 |
| 充值码超兑 | WHERE status='active' 条件 UPDATE |
| 支付回调重放 | pending → paid 原子状态锁定 |
| 并发订单 | 卡密先锁再发 + 幂等键 |
| 支付宝回调 | RSA2 验签（cf-core AlipayProvider） |
| Stripe Webhook | HMAC 签名验证（cf-core StripeProvider） |

## 环境变量

新增可选的支付环境变量：

| 变量 | 必需 | 说明 |
|------|:----:|------|
| `STRIPE_SECRET_KEY` | 否 | Stripe 密钥 |
| `STRIPE_WEBHOOK_SECRET` | 否 | Stripe Webhook 签名密钥 |
| `TRC20_WALLET_ADDRESS` | 否 | USDT TRC20 收款地址 |
| `TRONGRID_API_KEY` | 否 | TronGrid API Key |

> 所有新变量为**可选**，不配置时对应支付方式在前端不可见。由 wrangler secret put 设置。

## 快速变现建议

充值码系统是**零外部依赖**的变现路径，推荐阶梯：

### 第 1 步：启动充值码（立即）

1. 管理员后台批量生成充值码（比如 100 张 × 10 元）
2. 在微信/Telegram 卖出充值码
3. 用户在 `/vouchers/redeem` 兑付
4. 用户用余额在商城购买商品

**优势**：不需要支付宝商户资质、不需要 Stripe 公司注册、不需要 USDT 钱包

### 第 2 步：开启支付宝（1-3 天）

配置 ALIPAY_APP_ID + ALIPAY_PRIVATE_KEY + ALIPAY_PUBLIC_KEY
用户直接在站内扫码支付，自动发卡。

### 第 3 步：开启 Stripe（如需海外收款）

配置 STRIPE_SECRET_KEY + STRIPE_WEBHOOK_SECRET
需要 Stripe 账户（海外个人/公司都可申请）。

### 第 4 步：开启 USDT/TRC20（高阶）

配置 TRC20_WALLET_ADDRESS + TRONGRID_API_KEY
需要用户自行链上转账，适合大额交易。
