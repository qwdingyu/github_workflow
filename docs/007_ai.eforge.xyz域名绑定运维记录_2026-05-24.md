# ai.eforge.xyz 域名绑定运维记录

日期：2026-05-24

## 背景

当前项目已经部署在 Cloudflare Workers：

```text
https://gptsession2cpaandsub2api.mailforwdy.workers.dev/
```

用户希望使用正式子域名：

```text
https://ai.eforge.xyz/
```

目标不是迁移到 Cloudflare Pages，而是在现有 Workers 主线上完成域名、HTTPS、自动部署和验证闭环。

## 结论

`ai.eforge.xyz` 已通过 Cloudflare Workers Custom Domains API 绑定到 Worker：

```text
gptsession2cpaandsub2api
```

绑定状态：

```text
zone: eforge.xyz
hostname: ai.eforge.xyz
service: gptsession2cpaandsub2api
environment: production
enabled: true
```

访问验证：

```text
https://ai.eforge.xyz/ -> HTTP/2 200
```

## 为什么选择 Workers Custom Domains

当前项目的真实线上产品是 Workers，不是 Pages：

- `*.workers.dev` 地址已经可访问。
- Cloudflare 账号下 Pages projects 为空。
- Workers scripts 中存在 `gptsession2cpaandsub2api`。
- `wrangler.jsonc` 已配置 Workers Static Assets，资源目录是 `src/`。

因此最佳路径是：

```text
GitHub main
-> Cloudflare Workers Builds
-> Worker: gptsession2cpaandsub2api
-> Custom Domain: ai.eforge.xyz
```

不创建新的 Pages 项目，避免双部署、双域名和回源混乱。

## 权限检查

已确认可用：

- Workers Custom Domains 列表接口可读。
- Workers Custom Domains 写入接口可用。
- Worker custom domain 创建成功。

仍需注意：

- `zones/{zone_id}/dns_records` 读取仍返回认证错误。
- `zones/{zone_id}/workers/routes` 读取此前也返回认证错误。

这说明当前 token 对本次 Custom Domain 绑定够用，但不能视为完整 DNS 运维 token。

## 执行步骤

### 1. 确认现有 custom domains

命令模板：

```bash
CLOUDFLARE_API_TOKEN=<token> rtk curl -sS "https://api.cloudflare.com/client/v4/accounts/<account_id>/workers/domains" \
  -H "Authorization: Bearer ${CLOUDFLARE_API_TOKEN}"
```

本次执行前结果为空：

```text
domains: []
```

### 2. 绑定 ai.eforge.xyz

命令模板：

```bash
CLOUDFLARE_API_TOKEN=<token> rtk curl -sS -X PUT "https://api.cloudflare.com/client/v4/accounts/<account_id>/workers/domains" \
  -H "Authorization: Bearer ${CLOUDFLARE_API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"environment":"production","hostname":"ai.eforge.xyz","service":"gptsession2cpaandsub2api","zone_id":"<zone_id>"}'
```

本次成功返回的关键信息：

```text
hostname: ai.eforge.xyz
service: gptsession2cpaandsub2api
environment: production
enabled: true
```

### 3. 验证 HTTPS

命令：

```bash
rtk curl -I https://ai.eforge.xyz/
```

结果：

```text
HTTP/2 200
content-type: text/html
content-security-policy: default-src 'self'; ...; connect-src 'none'; ...
```

说明：

- HTTPS 证书已经生效。
- 自定义域名已经路由到 Worker。
- 关键安全响应头仍在。

### 4. 验证页面版本

命令：

```bash
rtk curl -sS https://ai.eforge.xyz/ | rtk rg "custom-domain-smoke"
```

验收标准：

```text

```

如果正式域名和 `workers.dev` 返回的 smoke marker 不一致，优先检查 Cloudflare Workers Builds 是否完成，其次检查缓存和 custom domain 状态。

## 踩坑记录

### 背景

最初容易把当前部署误判为 Cloudflare Pages，因为项目是静态站点。

### 原因

Cloudflare Pages 和 Workers 都能部署静态资源，但当前线上地址是 `workers.dev`，并且 Cloudflare API 显示 Pages projects 为空。

### 排查过程

1. 检查当前线上地址，确认是 `workers.dev`。
2. 查询 Cloudflare Pages projects，结果为空。
3. 查询 Workers scripts，确认存在 `gptsession2cpaandsub2api`。
4. 检查 `wrangler.jsonc`，确认 `assets.directory` 是 `./src`。
5. 查询 Workers Custom Domains，确认绑定前为空。
6. 使用 Workers Custom Domains API 写入 `ai.eforge.xyz`。
7. 使用 `curl -I` 验证 HTTPS 和安全响应头。

### 解决方案

保留 Workers 主线，使用 Workers Custom Domains 绑定正式子域名。

### 建议

- 不要为同一项目同时维护 Pages 和 Workers 两套部署。
- 正式入口使用 `ai.eforge.xyz`。
- 回退入口保留 `workers.dev`。
- 每次推送后同时验证两个入口。
- 出现在对话或日志里的 Cloudflare token 应视为已泄露，建议任务结束后轮换。

## 后续运维建议

1. 保持 `wrangler.jsonc` 的 `name` 与 Cloudflare Worker 名称一致。
2. 域名绑定优先使用 Workers Custom Domains，不用 Workers Routes，除非需要路径级路由。
3. 长期 token 应拆分为 Deploy Token、Readonly Ops Token、Domain Ops Token。
4. Domain Ops Token 只在域名变更时短期启用。
5. 所有部署、域名、证书、缓存异常都必须写入 `docs/`，按背景、原因、排查过程、解决方案、建议记录。
