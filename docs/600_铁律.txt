铁律：
1、每次代码变更，务必提交到代码仓库中，commit请使用中文；
2、所有的代码修改，都要同步文档；
3、开发过程中一定要有全局视野，顶层思路，并不能不停的打补丁；
4、我们的开发规范是不要做大而全的系统，而是做小而美的瑞士军刀，不要过度设计，不要过度开发；
5、所有的改动都有在分析清楚全局和代码的基础上，不要看局部，务必要慎重，而且要确保所有的环节都形成闭环，并进行详细的单元测试；
6、针对发现的问题和规范，规则，流程等，要全部保存到docs目录下， 尤其是针对采坑记录要按照（背景，原因，排查过程，解决方案，建议等等）一定写清楚；
6、不要不切实际，不要假大空，一切要站在落地的使用场景的角度考虑问题；
7、所有的项目文档，分析文档，采坑记录，都要记录在项目根目录下docs目录中。命名规范为：序号_中文文件名_日期.md，文件名不能含有空格。
8、所有的开发都需要围绕核心功能展开，必要在细节上占用太长时间（细节可以整理到docs目录下的todolist.md中），确保核心功能快速实现和上线；
9、针对所有的技术选型，算法，要采用行业最优的方和算法，务必要遵循行业最佳实践，千万不要重复造轮子，闭门造车，耽误时间，且维护成本高，除非涉及到商业机密的；
10、请使用rtk（节省token），mcp，skills提高效率；
11、在构建测试脚本的时候，在正常情况下一定要写正式的脚本，不要在测试的过程中写了删，删了写，来来回回的浪费时间和精力，而且没有知识沉淀，就算调试完毕成功的，也被删除了，需要坚决杜绝这种一次性重复的临时脚本。
12、针对核心代码，变量，常量，业务流程，务必在代码中补充详细的中文注释；
13、能够使用ORM的情况下，一定不要使用SQL，防止SQL注入或者数据库切换，造成原始的SQL频繁的修改，坚决不能发生；
14、Cloudflare Workers 项目首次部署后，必须立即通过 wrangler secret put 设置 ADMIN_TOKEN 等鉴权密钥，这是上线前置条件，不可跳过。CI 部署只推送代码，不设置 secret。执行 rotate 脚本前必须先确认 wrangler whoami 认证通过，否则脚本会静默退出导致密钥从未推送。
15、Vue/Element Plus 组件的模板必须有完整的标签闭合结构。遇到组件的布局异常（列堆叠、渲染错位等），**第一件事是审查 HTML 标签结构完整性**，而不是修改 CSS 或组件属性。缺失闭合标签（如 `</el-table>`）会直接破坏 Vue 模板编译，CSS 和布局属性无论怎么改都无法修复。
16、前端布局排错的优先级顺序：（1）审查 HTML 标签结构完整性 →（2）检查官方文档的 API 和属性 →（3）只在确认前两步无误后，才修改 CSS。严禁先入为主猜 CSS 问题。
17、AI 辅助开发中，AI 在看不到屏幕截图的情况下，遇到用户反馈页面异常（如"列堆成行"），必须逐行审查源代码结构，而不是反复猜测 CSS 问题。每轮修改前都要先确认结构完整性。连续 2 轮修不好必须换思路，不能在同一条错误路径上继续。
