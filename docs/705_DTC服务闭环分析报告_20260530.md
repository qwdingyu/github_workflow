# DTC 服务闭环分析报告

> 日期：2026-05-30
> 范围：前端（public/ 静态页面 + 客户端 JS）与后端（Worker API + Turso DB）的交互完整性

---

## 一、闭环定义

一个完整的用户请求生命周期：

```
用户输入 → 前端页面 → API 调用（可选）→ 后端处理 → DB 查询 → 响应 → 结果展示 → 用户可见
```

闭环的每一个环节都必须是连接的、可用的。

---

## 二、闭环断点分析

### 2.1 闭环断点 1（🔴 严重）：关键词搜索 → 404

**问题**：首页搜索框只做 `window.location.href = '/dtc/' + code + '.html'`，非精确 DTC 码格式时跳转到一个不存在的 HTML 页 → 直接 404

**触发场景**：用户搜索 "oxygen sensor"、"P042"（不全）、"check engine"、"BMW" 等非精确 DTC 码 → 全部 404

**影响**：所有关键词搜索场景全部中断。DTC 服务本质是一个"查码"工具，但用户不可能记住所有 21,000+ 个 DTC 码，关键词搜索是核心使用场景。

**前端原因**：`public/index.html` 搜索行为只有一种：`/dtc/{code}.html`
**后端原因**：后端 `/api/v1/dtc/search?q=...` 功能正常，但前端没调用它

**修复**：
- 新增 `public/search.html` — API 驱动的搜索结果页，支持关键词搜索、系统过滤、分页
- 改造 `public/index.html` 搜索逻辑：精确 DTC 码 → 跳静态页；其他 → 跳 `/search.html?q=...`
- 完整闭环：`搜索 → search.html → fetch /api/v1/dtc/search → 渲染结果列表 → 点击某个结果 → 跳 /dtc/{code}.html`

### 2.2 闭环断点 2（🟡 中等）：无 404 导航页

**问题**：任何不存在的路径返回空白 "Not Found"

**触发场景**：URL 拼写错误、过期链接、爬虫访问不存在页面

**修复**：新增 `public/404.html` — 自动检测 URL 中的 DTC 码模式并填充搜索框，引导用户搜索

### 2.3 闭环断点 3（🟢 低）：DTC 详情页无动态交互

**问题**：已生成的 19,000+ 个 DTC 详情页是纯静态 HTML，没有嵌入 JS 调用后端 API

**影响**：可控，SEO 页面本身是原子化内容（每页一个 DTC 码的完整描述），用户从搜索引擎跳转到这些页面后能看到全部信息。缺少的只是"在此页面搜索其他相关码"的便利功能。

### 2.4 闭环断点 4（🟢 低）：generate-pages.mjs 覆盖 _headers

**问题**：手动修改 `public/_headers` 后运行 `npm run generate:pages` 会被覆盖

**影响**：不影响功能。`generate-pages.mjs` 生成的 `_headers` 内容与手写的 `_headers` 功能一致，只是缓存策略不同。以手动版本为准（先部署再 generate），或反之均可。

## 三、修复后的闭环图

```
用户输入 "P0420"
  → index.html 搜索框
  → 正则检测：是精确 DTC 码
  → 跳转 /dtc/P0420.html（静态 SEO 页）
  → 用户看到完整故障信息 ✅

用户输入 "oxygen sensor"
  → index.html 搜索框
  → 正则检测：不是精确 DTC 码
  → 跳转 /search.html?q=oxygen+sensor
  → search.html fetch /api/v1/dtc/search?q=oxygen+sensor
  → 后端搜索 DB → 返回结果列表
  → search.html 渲染结果卡片
  → 用户点击某个结果 → 跳 /dtc/{code}.html ✅

用户输入 "/aaaaa"（不存在路径）
  → Worker 返回 404
  → 用户看到 404.html（含搜索框）
  → 引导搜索 ✅

用户从搜索引擎跳到 /dtc/P0420.html
  → 看到完整 DTC 信息（code/description/system/manufacturer）
  → 页面底部有搜索入口链接 → 可搜索其他码 ✅
```
