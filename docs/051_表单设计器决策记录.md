# 表单设计器决策记录

> 日期：2026-05-29
> 决策：不自建轻量 JSON 表单设计器

---

## 决策背景

用户提出关键问题：自建轻量 JSON 表单设计器（~800 行）是否会造成维护负担？是否会卡住几天？

## 风险评估

| 风险 | 严重度 | 说明 |
|------|:------:|------|
| 拖拽交互复杂度 | 🔴 高 | drag-and-drop UI 边界情况多（排序、嵌套、实时预览同步） |
| 开发周期不可控 | 🔴 高 | 预估 800 行，实际可能 1500+，容易卡 3-5 天 |
| 维护负担 | 🔴 高 | 独立开发者维护表单设计器 = 长期负担 |
| 偏离核心目标 | 🔴 高 | 在造基础设施，不是在造产品 |
| 用户还没提需求 | 🟡 中 | 没有真实用户反馈说"我需要可视化设计器" |

**结论：自建设计器是典型的"基础设施陷阱"。会卡住，会造成工作停滞。**

## 替代方案对比

| 方案 | 风险 | 维护负担 | 推荐度 |
|------|:----:|:--------:|:------:|
| A. 自建轻量设计器 | 🔴 高 | 🔴 高 | ❌ 不推荐 |
| B. 用 rjsf Playground 作为外部参考 | 🟡 中 | 🟢 低 | ⚠️ 可用但有依赖 |
| **C. 不建设计器，用现有 textarea** | 🟢 低 | 🟢 极低 | ✅ **最推荐** |
| D. admin.html 加"格式化 JSON"按钮 | 🟢 低 | 🟢 极低 | ✅ 推荐 |

## 最终决策：方案 C + D

**不自建设计器。** 理由：

1. **现有 admin.html 已有 JSON textarea 编辑器** — 已经够用
2. **rjsf Playground 是在线工具** — 用户可以打开 https://rjsf-team.github.io/react-jsonschema-form/ 设计表单，然后复制 JSON 粘贴到管理后台
3. **rjsf 是 Apache-2.0 开源** — 如果网站关了，可以 fork 自建，但那是以后的事
4. **如果 rjsf 关了怎么办？** — JSON Schema 是 W3C 标准，不会消失。设计器只是辅助工具，不是核心依赖
5. **真实用户反馈驱动** — 等有用户说"我想要可视化设计器"再考虑，现在不需要

## 关于"换标签"的问题

**答案：不换标签，不换路线。** 理由：

- cf-form 的 JSON 格式已经够简单（扁平数组，每个字段一个对象）
- 用户可以在 admin.html 直接编辑 JSON
- rjsf Playground 作为外部参考工具（不是依赖）
- 如果 rjsf 关了，用户可以继续用 textarea 编辑，或者 fork rjsf

**核心原则：不依赖任何外部网站作为核心功能。rjsf Playground 只是辅助工具，不是依赖。**
