# AcctBox 查询系统完整流程图（含 Email 查询）

## 一、问题陈述

用户反映：**"什么场景B还需要记录一个URL呢，lookupUrl 查询，不应该是记录一个类似订单号或者是这样的概念吗？让用户直接填写邮箱，用他的邮箱来查询他曾经下的订单呢？"**

这是业界最广泛的做法。用户的核心诉求是：
1. 订单号用户记不住，但邮箱记得住
2. 系统必须同时支持：订单号查询 **+** 邮箱查询 **+** 折扣码查询
3. 当系统参数 `require_email=true` 时，邮箱是必填项，查询时可用邮箱反查

## 二、三种业务场景完整流程图

### 场景 A：线下购买（Offline Pay）

```
用户选择商品
    ↓
点击「线下购买」
    ↓
前端：读取 require_email 配置
  ├── require_email=false → 邮箱字段隐藏，用户可直接下单
  └── require_email=true → 邮箱字段显示且必填
    ↓
前端调用 POST /api/pay/offline
  body: { productId, buyerEmail(可选或必填), couponCode(可选) }
    ↓
后端：
  1. 商品校验
  2. 折扣码 quote（可选）
  3. 创建订单（buyer_email 记录到 DB）
     status='pending', payment_method='offline', payment_note=订单号后6位
  4. 折扣码消耗 consume（如果用了折扣码）
  5. 写 order_event: "created"
    ↓
返回前端：
  { orderId, orderNo, orderToken, lookupUrl, amountCents }
前端展示：
  - 应付金额
  - 付款备注（orderNo 后6位）
  - 收款码（二维码）
    ↓
用户扫码付款（线下）
    ↓
点击「我已付款」
    ↓
前端：复用在线支付轮询弹窗
  轮询 GET /api/pay/status/:orderId（每5秒，最长10分钟）
  → 返回 status=pending/issued/delivered
    ↓
管理员在后台看到订单 → 确认收款 → 点击「标记已付款并发卡」
  POST /api/admin/orders/:id/mark-paid
    ↓
后端：
  1. markPaidAndIssue(DB, orderId)
  2. 原子发卡：SELECT available card → UPDATE cards status=issued
  3. UPDATE orders: status='issued', issued_card_id=卡ID
  4. 发邮件（如果有 buyerEmail 且 RESEND_API_KEY 配置了）
  5. 写 order_event: "issued"
    ↓
用户前端轮询到 status=issued
  → 展示交付信息（accountLabel, deliverySecret, deliveryNote）
    ↓
用户也可在查询页用以下方式找回：
  ├── orderToken → GET /api/orders/lookup?token=xxx
  ├── orderNo（订单号） → GET /api/orders/lookup?orderNo=xxx（新增）
  └── buyerEmail（邮箱） → GET /api/orders/lookup?email=xxx（新增）
```

### 场景 B：折扣码下单（前端通过折扣码直接领卡）

```
用户打开页面
    ↓
切换到「折扣码」标签页
    ↓
前端读取 require_email 配置
  ├── require_email=false → 邮箱字段隐藏
  └── require_email=true → 邮箱字段显示且必填（用户必须填）
    ↓
用户输入折扣码 [ + 邮箱（require_email=true时必填）]
    ↓
提交 POST /api/orders
  body: { couponCode, buyerEmail(可选或必填) }
    ↓
后端：
  1. 限流 enforceRateLimit
  2. Turnstile 验证码 verifyTurnstile
  3. 幂等检查（idempotency-key header）
  4. createOrder(c, input, ipHash)
     ├── getCoupon → 折扣码校验
     ├── getProduct → 商品校验
     ├── quoteCoupon → 报价
     ├── 如果 issue_mode='direct'：
     │   ├── 原子发卡（先扣卡再写订单，失败补偿释放）
     │   ├── consumeCoupon
     │   ├── status='issued'（直接完成）
     │   └── 返回交付信息（accountLabel, deliverySecret）
     └── 如果 issue_mode='manual'：
         ├── 创建 pending 订单（不提前发卡）
         ├── consumeCoupon
         ├── status='pending'
         └── 返回 lookupUrl（供用户查询）
    ↓
前端收到响应：
  ├── direct 模式：直接展示卡密（accountLabel, deliverySecret）
  └── manual 模式：展示「订单已创建，请等待」
    ↓
【问题发现】：前端没有收到 buyerEmail 用于后续邮件通知
  → 需要在 createOrder 返回中包含 buyerEmail
    ↓
用户如需找回（manual 模式）：
  ├── orderToken → GET /api/orders/lookup?token=xxx
  ├── couponCode（折扣码） → GET /api/orders/lookup?code=xxx
  └── buyerEmail（邮箱） → GET /api/orders/lookup?email=xxx（新增）
    ↓
管理员确认后发卡 → 邮件通知 → 用户通过邮件或查询页获取卡密
```

### 场景 C：在线支付（PayJS / 待替换）

```
用户选择商品
    ↓
点击「微信支付」
    ↓
前端调用 POST /api/pay/order
  body: { productId, couponCode(可选), buyerEmail(可选) }
    ↓
后端：
  1. 限流
  2. 商品校验 + 折扣码 quote（不消耗）
  3. 创建 pending 订单（status='pending', payment_method='online'）
  4. 请求 PayJS 获取二维码
  5. 保存 payjs_order_id 到 order_event
  6. 返回 { orderId, orderNo, qrcode }
    ↓
前端展示支付二维码
    ↓
用户扫码支付（微信/支付宝）
    ↓
PayJS 服务器回调 POST /api/pay/callback
    ↓
后端：
  1. 验证签名 verifyPayJSSign
  2. 查找订单
  3. 防止重复回调（status 检查）
  4. UPDATE orders: status='paid', paid_at=now
  5. consumeCoupon（如有折扣码）
  6. markPaidAndIssue → 自动发卡
  7. 发邮件通知（如果 buyerEmail 存在）
  8. 写 order_event: "paid", "issued"
    ↓
前端轮询 GET /api/pay/status/:orderId
  → 返回 status=issued → 展示交付信息
    ↓
用户也可通过以下方式查询：
  ├── orderToken（来自支付成功页）
  ├── orderNo（手动记录）
  └── buyerEmail → GET /api/orders/lookup?email=xxx（新增）
```

## 三、查询系统完整流程图（查询入口）

```
用户访问查询页 /lookup（或点击「查询」Tab）
    ↓
输入框placeholder：「订单 Token / 订单号 / 邮箱」
    ↓
用户输入内容提交
    ↓
自动判断输入类型（优先级如下）：
  1. 包含 @ 且有 . → 识别为 email
     → GET /api/orders/lookup?email=xxx
  2. 长度 > 40 字符 → 识别为 orderToken
     → GET /api/orders/lookup?token=xxx
  3. 其他情况 → 识别为 orderNo 或 couponCode（前端做2次请求试错）
     → 先试 GET /api/orders/lookup?orderNo=xxx
       → 404 再试 GET /api/orders/lookup?code=xxx
       → 再次 404 → 返回「未找到订单」

【新增】email 查询的完整流程：
    ↓
GET /api/orders/lookup?email=xxx
    ↓
后端：GET /api/orders/lookup
  查询参数：email
  → SELECT * FROM orders WHERE buyer_email = ?1
    ORDER BY created_at DESC
    LIMIT 10（邮箱可能对应多笔订单，返回列表让用户选）
    ↓
如果找到1笔订单：直接展示交付信息
如果找到多笔订单：展示订单列表让用户选择（显示 orderNo, productTitle, createdAt, status）
如果没找到：返回「未找到订单」
    ↓
【前端】展示查询结果（单笔或多笔列表）
```

## 四、系统参数 `require_email` 的完整校验链

```
前端：fetchConfig() → 读取 require_email

场景A（线下购买）：
  require_email=true
    → 邮箱字段显示 + required
    → 前端 FormData 包含 buyerEmail
    → POST /api/pay/offline { buyerEmail }
    → 后端 orders 表记录 buyer_email

场景B（折扣码下单）：
  require_email=true
    → 折扣码表单中邮箱字段必填
    → 前端校验：if (requireEmail && !buyerEmail) { 提示错误 }
    → POST /api/orders { buyerEmail }
    → 后端 orders 表记录 buyer_email

【Gap修复】：后端也需要强制校验 require_email
  在 orders.ts 的 createOrderSchema 中：
    buyerEmail: require_email=true 时 → .min(1) + email格式
    否则 → .optional()

  实现方式：在路由层读 system_config，再决定用哪个 schema 校验
  → 需要新接口 GET /api/system-config（公开白名单，不需要鉴权）
  → 前端已有，后端 orders.ts 路由层未使用
```

## 五、当前实现 vs 规范要求的差异清单

| 功能 | 当前实现 | 规范要求 | 状态 |
|------|---------|---------|------|
| Token 查询 | ✅ `GET /api/orders/lookup?token=` | ✅ | 已实现 |
| 折扣码查询 | ⚠️ 仅限 `max_uses=1` 的折扣码 | 应支持所有折扣码 + 邮箱二次验证 | 需修复 |
| 邮箱查询 | ❌ 不存在 | ✅ `GET /api/orders/lookup?email=` | 需新增 |
| 订单号查询 | ❌ 不存在 | ✅ `GET /api/orders/lookup?orderNo=` | 需新增 |
| Server 端 require_email | ❌ `buyerEmail` 是 `.optional()`，不校验 | 当 `require_email=true` 时强制校验 | 需修复 |
| 折扣码查询 + 邮箱验证 | ❌ 无 | 当 `require_email=true` 时，折扣码查询需同时验证邮箱 | 需新增 |
| 查询页 placeholder | 显示「订单 Token 或折扣码」 | 应显示「订单号 / Token / 邮箱」 | 需修改 |

## 六、修复计划

### Phase 1：查询入口增强（优先级最高）

1. **新增 `GET /api/orders/lookup?email=`**（email 查询）
2. **新增 `GET /api/orders/lookup?orderNo=`**（订单号查询）
3. **修改 `GET /api/orders/lookup`** 支持多参数联合查询
4. **修改前端 `lookupForm`** placeholder 改为「订单号 / Token / 邮箱」，自动识别输入类型

### Phase 2：Server 端 require_email 强制校验

5. **修改 `orders.ts` 路由层**：读取 `system_config` 表中 `require_email`，动态选择 Zod schema
6. **确保 `buyerEmail` 在 DB 中正确记录**

### Phase 3：折扣码查询增强

7. **修改 `getOrderByCouponCode`**：对所有 `max_uses` 折扣码开放查询，当 `require_email=true` 时要求同时提供 `buyerEmail` 做二次校验
8. **前端查询页**：折扣码查询时，若 `require_email=true` 同时提交 `buyerEmail`，后端做二次验证

### Phase 4：查询结果优化

9. **email 查询返回多笔订单时**：展示列表让用户选择
10. **所有查询结果**：统一展示 `orderNo`, `productTitle`, `createdAt`, `status`，已发卡的展示卡密

## 七、关键代码修改点

### 7.1 新增 email 查询路由（orders.ts）

```ts
orderRoute.get("/orders/lookup", async (c) => {
  const token = c.req.query("token")?.trim();
  const code = c.req.query("code")?.trim();
  const orderNo = c.req.query("orderNo")?.trim();
  const email = c.req.query("email")?.trim();
  
  // 优先级：token > email > orderNo > code
  if (token) {
    const order = await getOrderByToken(c.env.DB, token);
    if (!order) return fail(c, "订单不存在", 404);
    return ok(c, { order });
  }
  
  if (email) {
    const orders = await getOrderByEmail(c.env.DB, email);
    if (!orders || orders.length === 0) return fail(c, "未找到订单", 404);
    // 多笔返回列表，单笔返回详情
    return ok(c, orders.length === 1 
      ? { order: orders[0] } 
      : { orders: orders.map(safeOrder) });
  }
  
  if (orderNo) {
    const order = await getOrderByOrderNo(c.env.DB, orderNo);
    if (!order) return fail(c, "订单不存在", 404);
    return ok(c, { order });
  }
  
  if (code) {
    const order = await getOrderByCouponCode(c.env.DB, code);
    if (!order) return fail(c, "订单不存在", 404);
    return ok(c, { order });
  }
  
  return fail(c, "请输入订单 Token、订单号、邮箱或折扣码", 400);
});
```

### 7.2 新增 service 函数

```ts
// order-service.ts
export async function getOrderByEmail(db: D1Database, email: string) {
  const { results } = await db.prepare(`
    SELECT
      o.id, o.order_no AS orderNo, o.product_id AS productId,
      p.title AS productTitle,
      o.buyer_contact AS buyerContact, o.buyer_email AS buyerEmail,
      o.amount_cents AS amountCents, o.discount_cents AS discountCents,
      o.currency, o.status, o.issue_mode AS issueMode,
      o.issued_card_id AS issuedCardId, o.created_at AS createdAt
    FROM orders o
    JOIN products p ON p.id = o.product_id
    WHERE o.buyer_email = ?1
    ORDER BY o.created_at DESC
    LIMIT 10
  `).bind(email.toLowerCase()).all<OrderSummaryRow>();
  
  return results || [];
}

export async function getOrderByOrderNo(db: D1Database, orderNo: string) {
  const row = await db.prepare(`
    SELECT o.*, p.title AS productTitle
    FROM orders o
    JOIN products p ON p.id = o.product_id
    WHERE o.order_no = ?1 OR o.id = ?1
  `).bind(orderNo).first<OrderSummaryRow>();
  
  if (!row) return null;
  if (row.status !== "issued" || !row.issuedCardId) return publicOrder(row);
  
  const card = await db.prepare(`
    SELECT account_label, delivery_secret, delivery_note
    FROM cards WHERE id = ?1
  `).bind(row.issuedCardId).first();
  
  return publicOrder(row, card);
}
```

### 7.3 前端自动识别输入类型（app.js）

```js
lookupForm.addEventListener("submit", async (event) => {
  event.preventDefault();
  const value = String(new FormData(lookupForm).get("token") || "").trim();
  
  let query;
  if (value.includes("@") && value.includes(".")) {
    query = `email=${encodeURIComponent(value)}`;
  } else if (value.length > 40) {
    query = `token=${encodeURIComponent(value)}`;
  } else {
    // 先试 orderNo，再试 code
    try {
      const data = await api(`/api/orders/lookup?orderNo=${encodeURIComponent(value)}`);
      renderDelivery(lookupResult, data.order);
      return;
    } catch {}
    query = `code=${encodeURIComponent(value)}`;
  }
  
  const data = await api(`/api/orders/lookup?${query}`);
  if (data.orders) {
    // 多笔订单，展示列表
    renderOrderList(lookupResult, data.orders);
  } else {
    renderDelivery(lookupResult, data.order);
  }
});
```

## 八、完整数据流（从下单到查询的端到端）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              用户下单                                      │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
          ┌──────────────────────────┼──────────────────────────┐
          ↓                          ↓                          ↓
     【场景A】                   【场景B】                   【场景C】
     线下购买                    折扣码下单               在线支付
     /pay/offline               /orders                  /pay/order
          │                          │                          │
          ↓                          ↓                          ↓
   创建 pending 订单         折扣码校验                创建 pending 订单
   (payment_method=offline)  product 查询              (payment_method=online)
          │                 quoteCoupon                  │
          │                          │                     PayJS 回调
          │                          ↓                     /pay/callback
          │                    issue_mode?                  │
          │                    ├─ direct: 直接发卡         │
          │                    └─ manual: 待确认           │
          │                          │                     ↓
          ↓                          ↓              markPaidAndIssue
   管理员确认收款              写 orders 表            (自动发卡+邮件)
   /mark-paid                 buyer_email 记录         │
          │                          │                     ↓
          ↓                          ↓              订单完成
   markPaidAndIssue           等待管理员              用户查询
   (发卡+邮件)                手动发卡                 │
          │                          │                     │
          └──────────────────────────┼─────────────────────┘
                                     │
                                     ↓
                            【统一查询入口】
                            GET /api/orders/lookup
                              ├─ token=xxx  （orderToken）
                              ├─ orderNo=xxx（订单号）
                              ├─ email=xxx  （邮箱）
                              └─ code=xxx   （折扣码）
                                     │
                    ┌────────────────┼────────────────┐
                    ↓                ↓                ↓
              getOrderByToken  getOrderByEmail  getOrderByCouponCode
                    │                │                │
                    └────────────────┴────────────────┘
                                     │
                                     ↓
                              返回订单信息
                              (含交付卡密)
```
